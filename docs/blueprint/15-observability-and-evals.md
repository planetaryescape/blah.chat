## Reproducible gates before feature claims

S1 must establish an isolated frozen-lockfile install on agreed Bun/Node versions, rebuild dependencies from the same source, then run an explicit scope matrix. Use Bun only. Queue heavy local work through `agent-work`, with four or fewer workers; do not start every native app through root dev to test web.

| Gate | Required scope and failure behavior |
|---|---|
| Source inventory | Track actual commands and source roots, not Turbo graph nodes. Include backend offline typecheck and tracked shared/backend lint; currently only web/mobile/CLI lint exists. Account for nine legacy backend test files outside configured discovery |
| Dependency build | Build public package exports before consumers; fail on stale generated/dist provenance. Never repair a stale dist by asserting the source is wrong |
| Lint/typecheck/unit | Required tasks must exist and execute. Preserve separate web typecheck because Next's `ignoreBuildErrors` makes build alone insufficient. Seed a backend/shared violation to prove scope |
| Backend contract | Real Convex validators, authenticated fixtures, public aliases and actual action/tool builders. No permissive mock that accepts an unsupported argument or obsolete model message |
| Candidate UI | Serve the exact built candidate against its compatible isolated backend/seed/fake provider. Pin candidate source/artifact identity in the report. Required auth/seed failures are failures, not `test.skip` |
| Release | Build plus compatible backend/schema and cross-client evidence; use [17](17-cli.md)/[18](18-mobile-and-desktop.md) for affected clients |

The current [CI smoke](../../.github/workflows/ci.yml#L170-L245) targets `SMOKE_BASE_URL` or production, independently of the candidate. Keep that check labeled deployed liveness. It cannot substitute for candidate send → partial persistence → reload → completion. Existing durable E2E skips on missing auth and backend tests omit the main external-LLM action; the new fake-provider gate must close those specific gaps.

Inspect `package.json.scripts` for existence before execution. A declared build/typecheck/test runs once, visibly, and its nonzero exit blocks release. Never use `if command >/dev/null 2>&1` to call failure an absent script, `|| true`, swallowed subprocess status, a missing-auth skip, or an empty selected test set. Report selected/executed/skipped cases and assertion counts. Optional checks can be out of scope only when named before the run with an owner and a blocked release/capability; they are not passes. Test the gate itself with a declared command that exits 1 and a deliberately broken refresh fixture. (D-033; S1/S3)

## Metadata-first tracing

Keep structured Pino in API routes and the existing redacting Convex logger. Pass correlation explicitly through action/mutation/scheduler/tool boundaries: `requestId`, `conversationId`, `messageId`, `runId`, `attemptId`, persisted `toolCallId` and provider request ID where available. Do not assume an HTTP async context follows a scheduled Convex action. Treat IDs as private metadata with access/retention controls, not public labels.

Log an allowlisted event name, version, transition, safe error code, duration, counts, route/catalog/policy/prompt versions, attempt/lease identity, queue delay and measured/estimated/unknown usage classification. Persist execution facts in `runEvents` with bounded payloads and cursor ordering from [02](02-data-model.md); export only a redacted subset. `producer: orchestrator|executor|model` distinguishes actual execution evidence from model narration. Never present model planning text as a completed step.

Never export raw prompts, messages, tool args/results, skill files, connection profiles, URLs with queries, screenshots, audio, API keys, cookies, bearer tokens or OAuth state/code by default. Fix the [callback's whole-query logging](../../apps/web/src/app/api/composio/callback/route.ts#L25-L44) before adding an exporter. Test sentinel secrets in nested objects, error causes, URLs, browser reports and exporter buffers. Redact before every sink; downstream redaction alone is insufficient. Incognito disables content capture and follows the approved metadata/erasure policy, Q4. Private debugging capture needs explicit scope, bounded lifetime and deletion, not a global verbose switch. (D-034; S2/S16)

Operational dashboards should show oldest pending work, heartbeat age, stuck leases, waits, stop-to-quiescence, uncertain effects, failures by safe code, settlement lag, ledger reconciliation, connector cleanup backlog, blocked schedules, cache accounting completeness and exporter drops. Waiting for input/approval is not a stuck spinner or timeout error. Alert thresholds require S16 baselines and Q3 limits; this plan invents no measured SLO.

User-visible status follows Quiet workbench, Q2/D-023: saved answer/output and the blocking question remain primary; diagnostic IDs, raw events and detailed timings stay behind Details. An elapsed counter must not announce every tick or imply the executor is healthy. Use the same paused/failed/cancelled labels across web, CLI and native readers.

Tracing is optional evidence, not authority. A sampled trace cannot decide authorization, Run status or billing. `runAttempts` counts each physical retry; immutable `usageEvents` captures each billable call/step with `measurement: reported|estimated|unknown`, independent of sampling, exporter availability or token dashboards. Keep financial settlement and terminal transitions intact if an exporter fails. Record bounded exporter-failure metadata without turning a completed answer into an error. (D-016/D-034)

For S16, pin hardware/runtime/build, synthetic history/chunk cadence and worker limits. Record p50/p95 input-to-paint, end-to-end TTFT, reveal lag/final flush, parser/highlighter CPU, long tasks, DOM/heap, network/subscription bytes, Convex writes and prepend/follow anchors. Compare streaming, replay bursts, comparison runs, large completed blocks and disclosure/remount workloads. Set numeric regression targets only after this baseline and Q2 review; comments about 60fps or percentage improvements are not measurements.

## Optional answer-quality experiments

No Langfuse integration was found in the baseline. [Langfuse's reviewed docs](https://langfuse.com/docs/evaluation/overview.md) support datasets, deterministic evaluators, human annotation and optional model judges. The reviewed [documentation index](https://langfuse.com/llms.txt) warns of legacy Cloud API removal on 2026-11-16. Verify exact SDK/API/self-host compatibility when implementing; do not copy old telemetry or ingestion examples into AI SDK6/7. Langfuse is an optional redacted reporting backend, never a prerequisite for auth, durable execution or the ledger. (D-034; Q4/Q8/Q18)

Start with synthetic fixed responses and deterministic task/schema/code checks. Compare repaired routing bins and a single-model baseline before learned/hosted routers. Dataset consent precedes any private-history export. Split by conversation/time, keep near duplicates out of holdouts, pin candidate/model/prompt/adapter/catalog versions, and report slice sizes and uncertainty. Open-ended answers need blinded reviewed preferences, including tie/both-bad. Calibrate model judges against human labels and report disagreement; label accuracy is not answer quality. Include full classifier/retry/cache/tool cost and cache-cold/warm conditions. [Routing evidence](../../research_notes/blah-chat-modernization-review/routing-feature-disposition.md#3-what-should-be-kept-integrated-removed-tested-or-deferred) specifies the comparison, not a promised savings rate.

Live canaries are separate, manual and small. Q3 must set numeric call/token/compute/wall/concurrency/dollar limits and an abort rule; Q8/Q18 must approve providers/dataset/regions/terms. Start with selected synthetic side-effect-free tasks. Do not exercise real sends, authenticated desktops or scheduled writes merely to test a model. Save actual adapter/model/payer/pricing/cache identity and reconcile all attempts, including failures. No approval means zero paid calls.

## Release evidence and rollback

Retain the exact-artifact workflow in [packaging](../packaging.md#production-web-promotion), [release](../../.github/workflows/release.yml) and [rollback](../../.github/workflows/rollback.yml). Staging deploys compatible backend code before the web artifact; promotion does not redeploy it. Record source SHA, immutable deployment ID/URL, manifests/lock/runtime, generated binding/schema versions, backend compatibility range, executed gates and authorized migration/canary evidence. Verify the exact staged sign-in/send/refresh journey and retained old-client/run reads. Do not promote a rebuilt substitute or an unrelated healthy deployment.

The documented production-environment protection blocker was observed on 2026-11-02, not freshly verified in this review. An authorized operator must verify server-side environment policy before promotion; workflow conditions alone do not protect unrestricted secrets. Backend/schema rollout and production promotion each require approval. Keep [desktop automatic releases suspended](../packaging.md#independent-versioning-release-please).

Rollback documentation must identify the previous verified artifact and compatible backend, fields/runs/clients that must remain readable, migration pause/reconciliation procedure and stop/new-admission controls. Keep active runs on their recorded `runnerVersion`; do not replay unknown effects or undo financial facts. Do not contract a schema to make a rollback compile. A dependency rollback cannot silently restore an advisory-matched graph; use a verified patched alternative or explicitly disable/mitigate the affected capability. S1/S3/S8/S15/S17 and per-rung gates must supply evidence before release, not retrospective reassurance. (D-020/D-030/D-031/D-033)
