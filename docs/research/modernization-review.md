# Repair trust before expanding agent capabilities

blah.chat needs targeted repairs and new agent capabilities, not a replacement chat stack. The reviewed code already uses Next 16, React 19, AI SDK 6, Convex-backed durable generation, Streamdown, Shiki, a worker renderer and four client apps. The most urgent findings are public data-access and paid-action authorization gaps, destructive retry, incorrect payer/usage accounting, and tool-result contracts that undermine both existing UI and proposed autonomy. BK explicitly requested Smart Assistant removal, better narration, context compaction near 80%, caching, visual artifacts, richer questions/progress, E2B computer tasks, skills including self-authored skills, scheduling, and a fresh integrations/routing review. Those requirements are covered below; all implementation recommendations remain proposals. Preserve the existing durable producer, branching, normalized metadata, account-scoped cache and release safeguards while repairing their boundaries. No application code, package installation, paid inference, deployment or commit is part of this report.

## Private data and paid actions need first repair

Severity below is impact-based prioritization, not measured incident frequency. **P0 blocks expansion/release until fixed or disabled; P1 is high-impact correctness/privacy/spend; P2 is a material user/maintenance defect; P3 is lower-risk hygiene or a hypothesis requiring measurement.** Confidence refers to the source mechanism. None of the authorization findings was exploited against a deployment.

### P0: directly callable endpoints bypass otherwise useful controls

| Finding / confidence | Evidence and consequence | Repair and proof required |
|---|---|---|
| F01 / Critical / high: victim-ID full-text search | Public `fullTextSearch` accepts userId and returns matching full documents without identity. Public shares/notes expose owner IDs, so ID secrecy is not a defense. Both exported aliases must be protected. ([Source](https://github.com/planetaryescape/blah.chat/blob/04866f80a6236716ebf8d8c5a79001727f85f4bf/packages/backend/convex/search/hybrid.ts#L136-L168)) | Internal trusted primitive plus authenticated wrapper; owner/outsider/anonymous tests with identical search terms and an owner ID from a public-share fixture. |
| F02 / High / high: file extraction and RAG search | Public extraction reads arbitrary file storage; public vector search accepts userId, embeds and returns hydrated file/chunk content. Successful semantic results depend on indexed content/provider availability. ([Extraction](https://github.com/planetaryescape/blah.chat/blob/04866f80a6236716ebf8d8c5a79001727f85f4bf/packages/backend/convex/files/chunking.ts#L134-L170), [search](https://github.com/planetaryescape/blah.chat/blob/04866f80a6236716ebf8d8c5a79001727f85f4bf/packages/backend/convex/files/search.ts#L27-L106)) | Make pipeline-only actions internal; authenticated wrapper if clients need one. | F04 / High / high: anonymous paid AI | Selection summarization and task/meeting extraction ignore action identity and omit normal budget/accounting. Deadline parsing fans out. REST middleware cannot protect direct public Convex invocation. ([Summarization](https://github.com/planetaryescape/blah.chat/blob/04866f80a6236716ebf8d8c5a79001727f85f4bf/packages/backend/convex/generation.ts#L1975-L2021), [extraction](https://github.com/planetaryescape/blah.chat/blob/04866f80a6236716ebf8d8c5a79001727f85f4bf/packages/backend/convex/ai/taskExtraction.ts#L37-L125)) | Retire Smart Assistant endpoints completely; authenticate/bound/charge retained auxiliary actions. ## Build the requested agent experience on explicit durable contracts

### Preserve four different guarantees

Transport reconnect, persisted conversation state, journaled execution and external-effect/accounting idempotency solve different problems. Existing Convex subscriptions and partial rows already deliver refresh resilience. They should remain authoritative while a Run/Attempt/Tool call/Interaction layer adds ownership, real wait states, bounded cancellation and effect reconciliation. A scheduled action, workpool or workflow cannot prove an interrupted remote send never happened. Unknown outcomes must remain visible rather than replaying them through another account/provider. ([Runtime comparison and exact contracts](../../research_notes/blah-chat-modernization-review/agent-prior-art.md#keep-four-guarantees-separate), [Convex Workflow](https://github.com/get-convex/workflow), [Temporal effect caveat](https://docs.temporal.io/activity-definition#idempotency))

The proposed canonical Run states are `pending`, `running`, `waiting_for_input`, `waiting_for_approval`, `succeeded`, `failed`, `cancelled`. These do **not** exist in current message.status, which remains pending/generating/complete/stopped/error during migration. Preparing/compacting/retrying are phases; cancellation request and effect uncertainty are separate facts. Use one shared interactions store for questions/approvals, extend normalized toolCalls, and migrate canvas to one artifact owner. These names are planning contracts in [02](../blueprint/02-data-model.md), not claims about deployed tables. ([Decision log](../blueprint/21-decision-log.md), [open policies](../blueprint/22-open-questions.md))

### Context and routing must optimize the actual request

Automatic compaction should preserve the user's conversation and URL, not navigate to a new chat or rewrite transcript history. Plan the exact target-model serialization, including system/memory once, tools, selected skills, attachments, pending draft and output/reasoning uncertainty. Proposed usable input is `min(maxInput, combinedContext - outputReserve) - safetyReserve` where the provider actually has a combined limit; do not subtract output twice on a separate-input-limit API. Trigger near80% usable input or earlier for predicted tool growth, enforce fit on every provider step, then checkpoint an authorized older branch prefix and retain recent atomic tool groups. The threshold/default/tail/latency are Q6 assumptions, not fixed BK decisions. Summaries are lossy; immutable originals, explicit coverage, retrieval, validation and failure recovery are required. ([Context contracts](../../research_notes/blah-chat-modernization-review/context-caching.md#proposal-a-one-exact-request-plan-and-a-clear-denominator))

Cache optimization starts with deterministic stable prefix/tool ordering and moving fresh datetime from the early base prompt to a changing suffix without changing instruction authority. Browser Dexie, serialized application prompt fields and per-action maps are not provider KV caches. OpenAI/Gemini can have implicit hits without explicit code; current code lacks deliberate per-route policy and observability. Anthropic reads/writes, OpenAI old/new family retention/write billing and Gemini explicit object storage are different contracts. Native compaction artifacts are provider-specific, sometimes opaque/signed, and not portable to another model family. Locked SDK support differs from current docs, and Gateway forwarding must be tested. Do not enable extended TTL, stored histories or cross-user private caches to chase a hypothetical discount. ([Provider-by-provider exact support](../../research_notes/blah-chat-modernization-review/context-caching.md#what-do-current-provider-apis-and-the-pinned-ai-sdk-actually-support), [OpenAI](https://platform.openai.com/docs/guides/prompt-caching), [Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Gemini](https://ai.google.dev/gemini-api/docs/caching))

Routing should first enforce capabilities, actual serialized context, output reserve, allowed provider/account/payer, lifecycle, privacy and failed IDs on every fallback. Then use one curated catalog and deterministic baseline. The current classifier has no connected seed-embedding artifact, embeds before hard rules, loses previous route label, treats any attachment as vision, conflates price with quality and provider brand with speed, and orders research before high-stakes recognition. Explicit model choices must not silently route. Comparison votes can become consented evaluation data, but choosing/copying/retrying a model is not a clean quality label. ([Current route trace and evaluation suite](../../research_notes/blah-chat-modernization-review/routing-feature-disposition.md))

RouteLLM learns when a stronger model adds value, but its historical GPT4/Mixtral benchmark is not a current model ranking. CPT50 is half the weak-to-strong gap, not50% correctness; paper revision and README savings claims differ. RouterBench provides over405k historical inference outcomes. ACL2026 LLMRouterBench's verified publisher abstract reports21 datasets/33 models and warns many methods do not reliably beat simple baselines; this review did not reproduce its scores. Current OpenRouter Auto ranks task candidates by trailing market spend, not blinded quality, and its old Not Diamond description is stale. Not Diamond requires representative candidate responses/eval scores and a new data processor. Evaluate local pairwise routing against repaired bins/single-model baselines first; hosted variants and quality cascades are gated experiments, online bandits deferred. ([RouteLLM v4](https://arxiv.org/html/2406.18665v4), [RouterBench](https://arxiv.org/abs/2403.12031), [LLMRouterBench publisher](https://aclanthology.org/2026.findings-acl.1881/), [current OpenRouter Auto](https://openrouter.ai/docs/guides/routing/routers/auto-router), [Not Diamond training](https://docs.notdiamond.ai/docs/router-training-quickstart))

### E2B and skills add capability, not authority

E2B Desktop is a remote Linux environment plus input/output APIs, not the reasoning model or the user's own Mac. ## Conclusion

The requested agent features share a small set of hard problems: ownership, exact user intent, durable waiting, model-facing serialization, effect certainty and billable attempt identity. Solving those as explicit shared contracts makes each capability smaller to build and safer to stop. Adopting a new runtime or connector first would carry the same broken contracts into a larger system.

The best first release is therefore deliberately less autonomous: close public authorization/spend gaps and prove one correctly charged, durable user turn against the candidate artifact. Then expand what that reliable turn can produce, ask and schedule. BK's open policies determine which later capabilities can execute, not whether the report can recommend a safe path toward them.
