# Concurrency Audit 04 - Race Conditions

Scope: async/shared-state/event-driven paths only. Reviewed generation-v2 service/repository/store, SSE routes/consumers, Trigger.dev jobs, recovery/maintenance jobs, Dexie sync/queues, mobile queue/replay, CLI polling/streaming, and sampled document/canvas + embedding writes.

## Methodology

- Used `rg`/line-numbered reads against high-risk paths: `apps/web/src/lib/generation-v2/`, generation/stream routes, `packages/jobs/src/trigger/`, `apps/web/src/hooks/useRestMessageSync.ts`, `apps/mobile/lib/offline/`, `apps/mobile/lib/hooks/useMessages.ts`, `apps/cli/src/hooks/useMessages.ts`, cache/offline hooks, and canvas/document persistence.
- Looked for select-then-update races, missing CAS/idempotency, replay/dedup gaps, lost updates, retry double-execution, stale async writes, lifecycle cleanup issues, and status-transition holes.
- Did not mutate source. Only this report file was created.

## Findings

| id | priority | issue | evidence file:line | impact | recommended action | confidence |
|---|---|---|---|---|---|---|
| CONC-01 | P1 | Stop can lose to finalize after the last token. Cancellation is checked only inside the delta loop; after the loop the worker marks session/message complete without re-checking request/session cancel state. `cancelling` is non-terminal, so guarded updates still allow completion writes. | `apps/web/src/lib/generation-v2/service.ts:493`, `apps/web/src/lib/generation-v2/service.ts:531`, `apps/web/src/lib/generation-v2/repository.ts:1543`, `apps/web/src/lib/generation-v2/repository.ts:1476` | User hits stop and receives `cancelling`, but a just-finished worker can persist complete content/status and queue post-completion tasks. Timing-dependent trust bug. | Re-check request/session cancellation immediately before complete checkpoint/final emit. Make finalization a CAS from expected running status; if affected rows = 0, read actual status and avoid usage/background side effects. | High |
| CONC-02 | P1 | CLI stream consumer has no per-session sequence guard and handles `started` while server emits `start`. Replayed SSE deltas append onto current text after reconnect. | `packages/streaming-core/src/index.ts:17`, `apps/cli/src/hooks/useMessages.ts:61`, `apps/cli/src/hooks/useMessages.ts:67`, `apps/cli/src/hooks/useMessages.ts:177` | CLI output can duplicate streamed text or remain in the wrong pending/generating state after reconnect/replay. | Reuse `parseGenerationEvent` + web `GenerationStreamState` logic, reset content on `start`, and guard delta/checkpoint by highest seq per session. | High |
| CONC-03 | P1 | Mobile stream consumer also lacks seq guards/start reset and treats the first terminal event as the whole request being done. Comparison/multi-session requests can be truncated. | `apps/mobile/lib/chat/messageTree.ts:115`, `apps/mobile/lib/chat/messageTree.ts:123`, `apps/mobile/lib/hooks/useMessages.ts:118`, `apps/mobile/lib/hooks/useMessages.ts:135`, `apps/mobile/lib/hooks/useMessages.ts:139` | Reconnect replay can duplicate deltas; first completed model in comparison mode can clear active generation and stop listening before other model sessions finish. | Port web request-settled tracking: expected assistant IDs, seen IDs, terminal IDs, seq high-water per session, and only clear active generation after all expected sessions terminal. | High |
| CONC-04 | P1 | Mobile offline replay is not serialized. Reconnect and foreground both call `replayQueuedSends`; queue records marked `sending` are still returned by `list()`, and no in-process lock prevents two replays from processing the same record. | `apps/mobile/lib/offline/RuntimeBridge.tsx:78`, `apps/mobile/lib/offline/RuntimeBridge.tsx:81`, `apps/mobile/lib/offline/RuntimeBridge.tsx:88`, `apps/mobile/lib/offline/messageQueue.ts:184`, `apps/mobile/lib/offline/messageQueue.ts:194` | Duplicate sends; for local conversations, duplicate conversation creation before `localConversationId` is reconciled. Server `clientMessageId` helps only after a real conversation exists. | Add a replay mutex/lease. Skip fresh `sending` records or atomically claim records. Persist local-conversation reconciliation before send and make conversation creation idempotent for queued local sends. | High |
| CONC-05 | P2 | Stuck-message recovery marks `pending`/`generating` messages error but only marks `pending` sessions error. Generation-v2 sets sessions to `running`, while API maps message `streaming` to `generating`. | `packages/jobs/src/trigger/recover-stuck-messages.ts:27`, `packages/jobs/src/trigger/recover-stuck-messages.ts:48`, `apps/web/src/lib/generation-v2/service.ts:393`, `apps/web/src/lib/persistence/mappers.ts:52` | Recovered message can show error while its session/request remains active/running, so active-generation lookups and future status refresh may stay inconsistent. | Update stale sessions for recovered assistant IDs across `pending`, `running`, and `cancelling`; refresh parent request status after session updates. | High |
| CONC-06 | P2 | Generic `useSSE` hook sets `isMountedRef.current = false` in cleanup and never resets it when `endpoint` changes in the same component instance. | `apps/web/src/hooks/useSSE.ts:69`, `apps/web/src/hooks/useSSE.ts:132`, `apps/web/src/hooks/useSSE.ts:264`, `apps/web/src/hooks/useSSE.ts:276` | Endpoint changes can silently disable reconnect/polling because new `connectSSE`/`startPolling` calls return early. Timing/lifecycle dependent stale UI. | Set `isMountedRef.current = true` at the start of the effect for active endpoints, or replace it with an effect-local `cancelled` flag. | Medium |
| CONC-07 | P2 | SSE parser throws from `onError` inside callback, outside the async generator's normal control path. | `packages/api-client/src/sse.ts:47`, `packages/api-client/src/sse.ts:69`, `packages/api-client/src/sse.ts:74` | Malformed/interleaved stream chunks can escape cleanup/error handling differently than fetch/read errors, leaving CLI/mobile fallback behavior inconsistent. | Capture parser errors in a local variable/queue and throw from the read loop so consumers handle all stream failures uniformly. | Medium |
| CONC-08 | P3 | Embedding jobs can write stale embeddings after content changes while an older run is already embedding. Per-entity concurrency serializes queued runs, but there is no source `updatedAt`/version check at write time. | `packages/jobs/src/trigger/embed-note.ts:43`, `packages/jobs/src/trigger/embed-note.ts:56`, `packages/jobs/src/trigger/embed-note.ts:65`, `packages/jobs/src/trigger/embed-task.ts:43`, `packages/jobs/src/trigger/embed-message.ts:46` | Search can briefly or permanently reflect old note/task/message content if the fresh run fails after an older run overwrote the row. | Capture source `updatedAt` when read; before upsert, re-read or add a guarded write that skips if source changed. Include source version/timestamp in embedding metadata. | Medium |

## Checked / Not Findings

- Generation request creation has client-message idempotency and unique-violation recovery for web sends: `apps/web/src/lib/generation-v2/repository.ts:574`.
- Generation request processing has a pending-to-running claim guard for duplicate Trigger retries: `apps/web/src/lib/generation-v2/repository.ts:1404`.
- Web message streaming sync has a per-conversation write queue, flush-before-snapshot merge, and seq guards: `apps/web/src/hooks/useRestMessageSync.ts:490`, `apps/web/src/hooks/useRestMessageSync.ts:348`.
- Canvas/document updates use per-document advisory locks and optional expected-version conflict handling: `apps/web/src/lib/api/dal/canvas.ts:168`, `apps/web/src/lib/api/dal/canvas.ts:191`.
