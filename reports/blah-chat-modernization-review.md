# Repair trust before expanding agent capabilities

**The complete audit and research synthesis is [docs/research/modernization-review.md](../docs/research/modernization-review.md).** It contains all findings in severity order, measured-versus-static evidence, the compatibility/migration matrix, every requested feature's disposition, primary evidence/permalinks, source conflicts and all 15 raw research notes. This report is its concise entry point, not a second divergent copy.

blah.chat already has a modern stack and browser-refresh-resilient Convex generation. The first work should repair public authorization/spend gaps, destructive retry, wrong payer/usage accounting and broken structured tool results. A new agent framework would not repair those boundaries. BK's additions are all in scope: complete Smart Assistant removal; faithful list narration; roughly 80% automatic compaction and caching; visual HTML artifacts; better question/progress cards; E2B computer tasks; user-added and self-created skills; schedules; and current routing/integration research. No application code, installation, paid call, deployment or commit was performed for this planning deliverable.

## Compatible security cohorts come before elective migrations

Keep the durable producer and migrate independent cohorts. First candidates include coordinated AI SDK 6/provider maintenance, Mermaid 11, Vitest 4 patches and parent-specific transitive fixes. KaTeX requires tested 0.18/nested-edge work; parser/telemetry/native changes are migrations, not override fixes. AI SDK 7, Clerk Core 3, TypeScript 6→7 and Expo SDK steps need separate compatibility gates. **Observed Next 16.4.4 is not the announced November 3 security fix.** Recheck actual fixed release before implementation. ([Full matrix/advisory qualifications](../docs/research/modernization-review.md#upgrade-compatible-cohorts-instead-of-everything))

Local web lint and package-doc checks passed. Backend tests could not launch; web tests/typecheck failed in an incomplete installation with confirmed stale built exports. Those results do not establish clean-install upstream regressions. No production build, browser/device journey, real OAuth, inference, sandbox or heard audio was tested. ## New capabilities need shared durable authority

The proposed architecture retains Convex and adds shared Run/Attempt/Interaction/Artifact/Usage contracts. Convex Workflow is a preferred **spike**, not an approved replacement; Eve remains experimental. Start static isolated HTML, reviewed skill drafts/publication, user-enabled automatic activation, clean offline scripts, reviewed reminders then bounded read/draft automation. Consequential connector/computer writes, paid evals, retention and sharing remain gated. Repair Composio first and benchmark Nango as primary challenger; no provider is selected. Adapt pinned Notto hierarchy/state patterns, not its transport/theme or private code without permission. ([Feature disposition](../docs/research/modernization-review.md#feature-disposition-covers-every-explicit-addition), [provider comparison](../docs/research/modernization-review.md#compare-providers-by-a-safe-workflow-and-full-cost))

The proposed concept is **Quiet workbench**: preserve indigo/rose identity, make one answer/artifact primary, keep progress subordinate and human decisions visible. It is an assumption for BK to confirm, not an approved redesign. [Decision log](../docs/blueprint/21-decision-log.md) records 35 decisions/requirements/constraints with attribution; [open questions](../docs/blueprint/22-open-questions.md) defines 23 policy questions and 18 evidence spikes. The numbered blueprint turns the findings into session-sized usable releases, with separate permission for implementation and live changes.
