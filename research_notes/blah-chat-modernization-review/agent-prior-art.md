# Production multi-model chat and agent runtimes

Research cutoff and access date: **2026-11-03**. Every external URL below was accessed on that date. Registry versions are observed dist-tags, not guesses from documentation examples. Local links identify inspected repository evidence, not claims about deployed production. This was read-only research apart from this note. No experiments, installations, deployments, commits, or paid model calls were run.

## What should change in blah.chat's existing generation architecture?

### Takeaway

Keep server-owned Convex generation and reactive persistence. Modernize its execution records, accounting, message parts, and approval policy before choosing a replacement runtime. The verified latest stable AI SDK is 7.0.162, but this repository resolves 6.0.89 and has at least one upstream integration whose latest release still excludes v7. [AI registry](https://registry.npmjs.org/ai); [Tavily registry](https://registry.npmjs.org/@tavily%2Fai-sdk); [local lockfile](../../bun.lock)

### Cited findings

#### Actual baseline

- This is a Bun workspace, not an unimplemented Next.js chat template. Root `package.json` specifies Bun 1.3.5. The web manifest pins Next.js 16.4.3 and React 19.2.6; web and backend pin Convex 1.48.0 and declare `ai: ^6.0.3`. The lockfile resolves `ai@6.0.89`, OpenAI 3.0.29, Anthropic 3.0.45, Google 3.0.29, and Gateway 3.0.49. Declared ranges must not be reported as installed versions. [Root manifest](../../package.json); [web manifest](../../apps/web/package.json); [backend manifest](../../packages/backend/package.json); [lockfile](../../bun.lock)
- `packages/backend/convex/generation.ts` is a Node internal action. It creates or reuses an assistant message, admits generation through a mutation, runs `streamText`, persists partial text and reasoning, upserts normalized tool-call rows, and schedules alternate-model retries. It already has a 15-step stop condition, comparison groups, routing, attachments, custom prompts, and provider-specific reasoning. A wholesale replacement would have to preserve these behaviors. [generation.ts](../../packages/backend/convex/generation.ts#L113)
- The stream loop writes accumulated text snapshots on a 50 ms interval and checks durable stop status while processing arriving chunks. UTF-8-safe buffers preserve surrogate pairs. Terminal-state guards reject late partial writes. This provides browser-disconnect resilience through server-owned work and persisted state, but the inspected action does not journal each model/tool execution as a recoverable workflow step. [Stream loop](../../packages/backend/convex/generation.ts#L794); [partial-write guards](../../packages/backend/convex/messages.ts#L706)
- Stop checks are chunk-driven, not an independent 10 ms cancellation service. The loop can only inspect the stop flag after its next `fullStream` item arrives. A long silent provider or tool operation needs a separate cancellation mechanism and cooperative signal propagation. The normal aborted-loop path returns before the final usage calculation. This is an accounting test target, not proof that every stopped request is currently unaccounted. [Stop loop and early return](../../packages/backend/convex/generation.ts#L832); [final accounting](../../packages/backend/convex/generation.ts#L1157)
- `startGeneration` admits only a pending assistant message. `releaseLock` supports a lock ID, protecting a replacement lock against stale release. Existing locking is valuable and should not disappear during a runtime migration. Its documented 60-second staleness and comparison `pendingCount` also mean it is not interchangeable with an indefinitely parked approval workflow. [Admission](../../packages/backend/convex/messages.ts#L636); [generation locks](../../packages/backend/convex/lib/generationLock.ts#L17)
- `completeMessage` schedules accounting when completing a message; its stopped/error handling differs from normal completion, and the normal path has no early return for an already-complete message. `recordTextGeneration` increments a daily aggregate without accepting an operation/idempotency key. A retried accounting submission can therefore add the same usage again. This is application-level duplicate submission, distinct from Convex retrying a single transaction safely. [Completion](../../packages/backend/convex/messages.ts#L788); [accounting mutation](../../packages/backend/convex/usage/mutations.ts#L76); [usage schema](../../packages/backend/convex/schema.ts#L1019)
- Tool persistence has a normalized `toolCalls` table with native JSON, a provider-generated tool-call ID, `isPartial`, and a character position. The web renderer reconstructs tool/text ordering from those character positions and merges legacy/partial arrays. It does not have an explicit persisted approval/execution state machine in this schema. [Tool schema](../../packages/backend/convex/schema.ts#L453); [inline renderer](../../apps/web/src/components/chat/InlineToolCallContent.tsx#L7)
- Historical model input is reconstructed from text, attachments, timestamps, and `providerMetadata`; it does not reconstruct a typed historical tool-call/result transcript in the inspected serializer. Preserve the existing provider metadata while adding typed parts. [History serializer](../../packages/backend/convex/generation/history.ts#L42)
- The catalog already distinguishes model creator, gateway, and inference host. `getModel` supports explicit overrides, `actualModelId`, direct providers, and a default-model Groq/Cerebras fallback that avoids accidentally routing through a paid gateway. `ModelConfig` has capabilities, tiered prices, reasoning config, deprecation, and host order. Extend this boundary rather than adding model IDs to UI or runtime code. [Registry](../../packages/ai/src/registry.ts#L14); [model configuration](../../packages/ai/src/models.ts#L31)
- Application tools already respect incognito and read/write distinctions. Active Composio integrations can expose up to 100 retrieved tools, whose executors are wrapped for connection usage/error handling. No explicit approval gate appears in the inspected factory/wrapper. This makes server-enforced tool policy a more immediate need than replacing the tool-loop API. [Tool construction](../../packages/backend/convex/generation/tools.ts#L78); [Composio wrapper](../../packages/backend/convex/composio/tools.ts#L59)
- `convex.config.ts` installs Resend only. Workpool is present transitively through Resend in `bun.lock`, but the application does not thereby have an explicitly configured generation workpool, Workflow component, or Agent component. [Component configuration](../../packages/backend/convex/convex.config.ts); [lockfile](../../bun.lock)

- AI SDK 7 requires Node >=22 and is ESM-only. Convex currently supports Node 22/24 and defaults Node actions to 24. Local `packages/backend/convex.json` does not override that version, but deployment configuration still needs verification before migration. [Migration guide](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0); [Convex runtimes](https://docs.convex.dev/functions/runtimes); [local config](../../packages/backend/convex.json)
- v7 changes more than names: `result.usage` now aggregates all steps rather than only the final step; `prepareStep` message/instruction overrides carry forward; system messages inside history are rejected by default; media parts change; step response messages stop accumulating; and telemetry becomes an explicitly registered integration. Core renames include `stepCountIs` to `isStepCount`, `fullStream` to `stream`, and `onStepFinish` to `onStepEnd`. Some old names remain deprecated aliases. [v7 migration guide](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0)
- This directly touches `generation.ts`, which calculates cost from `await result.usage` plus a separate continuation, and `history.ts`, which allows system roles and image parts. The existing `createOnStepFinish` computes a discarded array; it does not currently supply a per-step usage ledger. The v6 path should be tested for final-step undercounting now, independently of a v7 upgrade. [Cost calculation](../../packages/backend/convex/generation.ts#L1157); [history](../../packages/backend/convex/generation/history.ts#L48); [callback](../../packages/backend/convex/generation/tools.ts#L367); [usage semantics](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0#multi-step-result-shape)
- Core v7 moves approval policy toward call/agent-level `toolApproval`; `needsApproval` is deprecated there. `WorkflowAgent` still documents `needsApproval` specifically. These APIs must not be mixed by analogy. v7 also introduces per-tool typed `toolsContext`, separate from shared `runtimeContext`; this limits what data a tool receives but does not sandbox trusted executor code. [Migration guide](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0); [WorkflowAgent](https://ai-sdk.dev/docs/agents/workflow-agent)
- Provider support remains model-specific, including object generation, tool streaming, and media. The official compatibility matrix explicitly says it is not exhaustive. A unified SDK call is not evidence that every model/gateway combination supports the same behavior. [Provider matrix](https://ai-sdk.dev/providers/ai-sdk-providers)

### Inferences

- Prefer an adapter around the current generation engine that owns durable run/attempt identity, ordered typed events, usage accounting, and cancellation. Provider SDK and runtime changes can then be tested without changing the web subscription contract at the same time. Existing boundaries already supply the necessary starting points. [Generation](../../packages/backend/convex/generation.ts); [registry](../../packages/ai/src/registry.ts); [messages](../../packages/backend/convex/messages.ts)
- Track both a logical operation and physical provider attempts. Deduplicate ingestion of the same provider attempt, but do not hide genuine extra provider charges when an interrupted LLM call executes again. A workflow engine cannot retroactively make an already-sent inference request free. [Workpool idempotency](https://github.com/convex/workpool#idempotency); [Eve recovery contract](https://eve.dev/docs/concepts/execution-model-and-durability#resuming-after-a-crash)
- Expand the catalog with versioned capability evidence per model/gateway/host, including schema strictness, media types, tool streaming, parallel tools, reasoning controls, provider-executed tools, and lifecycle status. Store the resolved API model ID, catalog/pricing version, actual route, SDK version, prompt version, and fallback chain on each attempt. Keep historical catalog entries resolvable. This extends existing deprecation and routing features rather than replacing them. [Local catalog](../../packages/ai/src/models.ts#L31); [registry](../../packages/ai/src/registry.ts#L43); [provider differences](https://ai-sdk.dev/providers/ai-sdk-providers)

### Gaps

- This was not a full production incident or billing audit. Actual hosted runtime settings, provider invoices, stop-path usage coverage, provider request IDs, and failure frequency were not queried. The accounting issues above are concrete source-level risks requiring deterministic tests and later authorized reconciliation. [Inspected accounting](../../packages/backend/convex/usage/mutations.ts#L76)
- Tavily's published peer range does not establish that v7 fails at runtime, only that support is not declared. Resolve through an upstream-supported release or a separately tested local tool adapter over its underlying client before upgrading production. [Registry](https://registry.npmjs.org/@tavily%2Fai-sdk)
- No latency, throughput, or total-cost improvement is claimed for SDK 7. That requires workload measurements; a newer stable version alone is not evidence of an application-level win. [Breaking-change scope](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0)

## Which durable runtimes and maintained chat implementations are useful prior art?

### Takeaway

Convex Workflow is the first durability candidate because data, subscriptions, auth, and mutations already live in Convex. Vercel Workflow/WorkflowAgent is a real alternative when there is a concrete reason to move compute. Eve supplies more of the application framework, but its release-candidate status and existing failed recovery probes argue for a bounded spike, not a production rewrite. [Convex workflows](https://docs.convex.dev/agents/workflows); [WorkflowAgent](https://ai-sdk.dev/docs/agents/workflow-agent); [Eve registry](https://registry.npmjs.org/eve); [local spike](../../experiments/eve-runtime/results/2026-11-01T23-07-15.439Z-0d46760f/summary.json)

### Cited findings

#### Keep four guarantees separate

| Guarantee | What it does | What it does not do | Evidence |
| --- | --- | --- | --- |
| Transport resumption | Reconnect/replay a previously produced stream using a cursor or stored chunks | Restart a dead compute process or suppress repeated external writes | [AI SDK resume guide](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-resume-streams) |
| Durable conversation state | Preserve user messages, partial answers, tool outputs for new subscribers | Automatically checkpoint the program counter of a model/tool loop | [Convex asynchronous streaming](https://docs.convex.dev/agents/streaming); [local action](../../packages/backend/convex/generation.ts#L794) |
| Durable execution | Journal completed steps, retry unfinished work, park for events | Guarantee an interrupted API call did not already take effect | [Convex Workflow](https://github.com/get-convex/workflow); [Workflow idempotency](https://workflow-sdk.dev/docs/foundations/idempotency) |
| Effect/accounting idempotency | Atomically deduplicate a domain operation and use provider-side idempotency/reconciliation | Force every third-party API or LLM provider to offer exactly-once execution | [Temporal activity contract](https://docs.temporal.io/activity-definition#idempotency); [Workpool example](https://github.com/convex/workpool#idempotency) |

- The AI SDK's Redis-backed resumable-stream recipe requires message/stream persistence, Redis, and resume endpoints. Client `stop()` is a disconnect in that design; explicit server-side stop must cancel producer work and clear only the matching active stream. Adding this recipe to blah.chat would duplicate an existing persistence/subscription function unless there is a measured transport requirement. [Resume and stop semantics](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-resume-streams)

- Workflow SDK separates cooperative `AbortSignal` cancellation from `run.cancel()`. Run cancellation stops workflow progression but does not automatically abort executing steps. For durable user stop, route an authorized control through a hook and signal-aware operations, then stop progression; a caller-process AbortController alone does not survive that caller's death. [Cancellation docs](https://workflow-sdk.dev/docs/foundations/cancellation)
- WorkflowAgent supports HMAC-signed approvals bound to approval ID, call ID, tool name, and validated input. Secret values are read in steps through an environment-variable reference rather than serialized as workflow arguments. Signatures authenticate the original request payload; the application still must authorize who may approve and prevent replay after the decision is consumed. [Signed approvals](https://ai-sdk.dev/docs/agents/workflow-agent#signed-tool-approvals)
- Documentation conflict to preserve: the WorkflowAgent page says approval suspends/resumes automatically, but its explicit approval round-trip example and the Nov 2 official comparison require a later invocation with approved history; a same-run parked wait uses a workflow hook. Some retry-attempt wording also differs between pages. Design to the concrete round-trip/hook contract and configure retry counts explicitly, then verify against pinned source. Do not promise automatic same-run parking from `needsApproval` alone. [Agent page](https://ai-sdk.dev/docs/agents/workflow-agent); [official comparison](https://vercel.com/kb/guide/eve-vs-ai-sdk-agents-vs-workflowagent); [implementation](https://github.com/vercel/ai/blob/main/packages/workflow/src/workflow-agent.ts)

#### Existing Eve experiment, preserved as evidence

- The local installed package and generated agent summary identify **1.0.0-rc.1**, while the Nov 3 registry identifies rc.2. The experiment has generated `.eve/.workflow-data`, output, installed dependencies, and results. No project-source repair or experiment rerun was attempted. [Installed manifest](../../experiments/eve-runtime/node_modules/eve/package.json); [generated summary](../../experiments/eve-runtime/.eve/agent-summary.json); [current registry](https://registry.npmjs.org/eve)
- The inspected latest timestamped summary is explicitly `mode: scripted-v3-model`. It records successful unauthenticated rejection, pricing-code execution, approval survival/deduplication, denial without write, terminal cancellation, and synthetic usage delivery. It also records **timeouts for sandbox filesystem survival across crash and for recovery during an active tool**. The reconnect case reports `eventsAfterCursor: 0`, so it should not be promoted into proof of live post-cursor continuation. [Summary](../../experiments/eve-runtime/results/2026-11-01T23-07-15.439Z-0d46760f/summary.json)
- `usage.jsonl` marks records `synthetic: true`. Its cost numbers test integration with local pricing, not real-provider invoice reconciliation. A unique local accounting key is useful but does not prove exactly-once provider billing. [Usage fixture](../../experiments/eve-runtime/results/usage.jsonl)
- Current upstream Eve documents checkpointed model/tool steps, but interrupted model calls may run again. Tool starts not durably recorded can repeat; even recorded interrupted effects can prompt a new model-issued call. It explicitly requires stable operation IDs for irreversible effects. On non-Vercel worlds, version changes can strand sessions; on Vercel, idle sessions can hand off while newer checkpoints can prevent rollback to older code. These are migration/rollback constraints, not incidental implementation details. [Execution and recovery](https://eve.dev/docs/concepts/execution-model-and-durability)
- Eve's local workflow store is not its sandbox filesystem. Upstream says Nitro serves routes, Workflow worlds hold workflow state, and sandbox providers own filesystem/process state. `just-bash` is an in-process virtual shell with a weaker boundary than a microVM/container. Do not interpret local durable workflow files as proof of durable isolated workspace recovery. [Execution model](https://eve.dev/docs/concepts/execution-model-and-durability); [security model](https://eve.dev/docs/concepts/security-model)

#### Verified infrastructure costs

- Vercel Workflow lists **$0.02/1,000 workflow events**, **$0.50/GB written**, and **$0.50/GB-month retained**. Hobby includes 50,000 events/month and 1 GB written; retained storage is unavailable on Hobby. Functions and Queues are additional charges. A normal step produces three events before retries. Do not use an older per-step price or count only model tokens when comparing engines. [Pricing](https://vercel.com/docs/workflows/pricing)

### Inferences

- A modern production design for this stack can remain Convex-centric: an authenticated command creates one run; a bounded durable loop records typed events and execution/usage outcomes; Convex queries project them to all clients. [Convex streaming](https://docs.convex.dev/agents/streaming); [Workflow](https://github.com/get-convex/workflow); [assistant-ui external store](https://github.com/assistant-ui/assistant-ui/blob/a96e62f89da310602b716821dd91b9525f94cbb5/packages/core/src/runtimes/external-store/external-store-adapter.ts)

## What should be kept, adopted, spiked, rejected, or deferred, and how should it ship safely?

### Takeaway

The highest-value work is explicit run identity, idempotent usage/effect records, server-authorized approvals, typed message parts, and failure-oriented evaluation. A runtime replacement comes after those contracts, with the old action available for new runs during rollback. Convex Workflow is the preferred experiment; replacing durable generation with request-bound `useChat` is rejected. #### Prompt-injection controls to implement regardless of runtime

1. Treat retrieved URLs, files, search results, memory content, tool descriptions from integrations, and resumed history as untrusted data. Keep trusted server instructions separate; reject client-supplied system roles rather than globally opting into `allowSystemInMessages`. Validate stored approval changes instead of replaying arbitrary client message parts. [SDK v7 message trust boundary](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0); [canonical-history pattern](https://github.com/vercel/chatbot/blob/8603c8ea35ded822811d3201812e717b22edbbab/app/(chat)/api/chat/route.ts)
2. Enforce permissions and allowed targets inside every executor. Determine user/tenant from authenticated server context, not model arguments; revalidate current access at execution/resume, including revoked OAuth connections. Dynamic integrations must not implicitly grant every retrieved write tool. Prefer an allowlist and a server-owned read/write/destructive classification. [Existing dynamic integration path](../../packages/backend/convex/composio/tools.ts); [resume ownership pattern](https://github.com/danny-avila/LibreChat/blob/f4154b649efa37e1345ccc517a4d8d1ed2178c82/api/server/controllers/agents/resume.js); [Eve auth boundaries](https://eve.dev/docs/concepts/security-model)
3. Require explicit approval for consequential external writes, including exact destination and validated arguments. Reapproval is needed when inputs, principal, target, tool/schema, or policy change. Denial/expiry never executes; consuming the same decision twice is a no-op. HMAC signatures, when used, complement database authorization/consumption rather than replace them. [Signed payload binding](https://ai-sdk.dev/docs/agents/workflow-agent#signed-tool-approvals); [LibreChat stale-action checks](https://github.com/danny-avila/LibreChat/blob/f4154b649efa37e1345ccc517a4d8d1ed2178c82/api/server/controllers/agents/resume.js)
4. Keep provider/integration credentials out of prompts, event payloads, sandbox environments, and traces. Give tools only the server context they require. Enforce URL/network/redirect/size rules in the actual fetch implementation and sandbox egress, not just a Zod URL validator. The inspected URL tool delegates to another action, so this note does not assert that downstream SSRF defenses are absent. [URL wrapper](../../packages/backend/convex/ai/tools/urlReader.ts); [Eve sandbox/security distinctions](https://eve.dev/docs/concepts/security-model); [telemetry masking](https://langfuse.com/docs/observability/features/masking.md)
5. Use prompt-injection fixtures that attempt to turn web/file/tool output into integration writes or cross-user reads. Grade the executed operations and authorization outcomes, not whether the assistant politely refuses in text. Preserve incognito's tool restrictions and disable content export before enabling default telemetry. [Existing incognito tool rules](../../packages/backend/convex/generation/tools.ts#L90); [deterministic evaluation gates](https://langfuse.com/docs/evaluation/experiments/experiments-ci-cd.md)

#### Migration, rollback, and acceptance criteria

The sequence below is proposed. Thresholds are proposed acceptance requirements, not measured results.

1. **Baseline and accounting first.** Add fake-provider/fake-tool tests around existing `generation.ts`, not a second production execution path. Cover multi-step calls, continuation calls, fallback attempts, cached/reasoning tokens, stopped/failed generations, and duplicate completion/accounting delivery. Add the attempt ledger before enabling retries. Accept only when duplicate ingestion changes no aggregate, every known physical call appears once, and unknown usage is explicitly marked rather than fabricated. Compare v6 final-step versus all-step totals. [Current usage path](../../packages/backend/convex/generation.ts#L1157); [aggregation](../../packages/backend/convex/usage/mutations.ts#L76); [v7 usage changes](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0#multi-step-result-shape)
2. **Additive schema and typed parts.** Add optional run, event, approval, and ledger data without deleting legacy fields. Assign stable IDs, sequence numbers, attempt epochs, and schema versions. Dual-project into legacy text/tool output while new readers are tested. Accept matching text/tool/source ordering, emoji/CJK integrity, attachment visibility, branching/comparison behavior, and reconstruction after a full reload. Historical messages remain readable. [Existing projection](../../apps/web/src/components/chat/InlineToolCallContent.tsx); [history](../../packages/backend/convex/generation/history.ts); [snapshot-versus-parts pattern](https://docs.convex.dev/agents/streaming)
3. **SDK update in isolation.** Resolve Tavily and Composio/OpenRouter compatibility, then pin the chosen stable package set in Bun's lockfile. Run provider contract fixtures for strict schemas, tools/results, media, reasoning metadata/signatures, and mixed-provider history. Accept reconciled all-step usage and no unexpected system-role acceptance. Do not change engine and frontend transport in this release. [Migration guide](https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0); [Tavily gap](https://registry.npmjs.org/@tavily%2Fai-sdk); [Composio peers](https://registry.npmjs.org/@composio%2Fvercel)

Accept zero unauthorized effects and zero duplicate domain effects in the fault matrix. Run cancellation prevents further model dispatch; cooperative abort reaches supported in-flight operations. Non-cancellable effects retain truthful state. [LibreChat contract](https://github.com/danny-avila/LibreChat/blob/f4154b649efa37e1345ccc517a4d8d1ed2178c82/api/server/controllers/agents/resume.js); [cooperative cancellation](https://workflow-sdk.dev/docs/foundations/cancellation); [Convex cancellation limit](https://github.com/get-convex/workflow#canceling-a-workflow)

Include two clients, disconnect before/after a tool, silent providers, deployment changes, and repeated queue deliveries. Accept that completed checkpointed steps do not rerun; uncertain external effects dedupe or become unknown; stale workers cannot overwrite the replacement attempt; and resumed output has neither omissions nor duplicate parts. [Workflow replay](https://github.com/get-convex/workflow); [local failures](../../experiments/eve-runtime/results/2026-11-01T23-07-15.439Z-0d46760f/summary.json); [resume race tests](https://github.com/danny-avila/LibreChat/blob/f4154b649efa37e1345ccc517a4d8d1ed2178c82/packages/api/src/stream/__tests__/GenerationJobManager.resumeReplay.spec.ts)

Keep critical correctness cases as hard gates even when aggregate quality improves. [Workpool overhead](https://github.com/convex/workpool#optimizations-with-and-without-workpool); [CI baseline policy](https://langfuse.com/docs/evaluation/experiments/experiments-ci-cd.md); [Workflow cost units](https://vercel.com/docs/workflows/pricing)

Start with internal opt-in conversations; do not dual-execute real tools or model calls for shadow comparison. Rollback sends only new runs to the old engine. Existing runs stay with their version or finish/cancel through that engine's authorized recovery path. Keep new fields optional, legacy projections available, workflow implementations stable, and external-effect keys common across adapters. Drain old runs before removing old code. [Convex replay constraints](https://github.com/get-convex/workflow#limitations); [Eve deployment/stranding constraints](https://eve.dev/docs/concepts/execution-model-and-durability)
