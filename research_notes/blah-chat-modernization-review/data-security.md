# Data, authentication, privacy, cost and cross-client audit

## Which trust boundaries still permit unauthorized access or spend?

### Takeaway

The current checkout contains meaningful recent hardening, but several older public Convex endpoints bypass it. Prioritize the directly callable search/file/source endpoints and anonymous paid actions before architectural modernization. These are source-traced findings, not claims that production exploitation occurred.

### Cited Findings

#### DS-01 — Critical: public full-text search accepts the victim's user ID as authorization

- **Evidence / trace:** `fullTextSearch` is a public `query`, takes `userId`, queries messages with that caller-supplied value, and returns complete message documents without checking identity: [packages/backend/convex/search/hybrid.ts:136–168](../../packages/backend/convex/search/hybrid.ts#L136). It is also re-exported as `api.search.fullTextSearch`: [packages/backend/convex/search.ts:1–2](../../packages/backend/convex/search.ts#L1). The normal `hybridSearch` wrapper correctly resolves the current user before calling it, but that wrapper does not protect direct public invocation: [search/hybrid.ts:28–58](../../packages/backend/convex/search/hybrid.ts#L28).
- **Impact:** an anonymous caller knowing a user's Convex ID can search that user's private message bodies, independent of conversation membership. Public share metadata and public notes disclose owner IDs, providing a concrete ID-discovery path: [shares.ts:147–155](../../packages/backend/convex/shares.ts#L147), [notes.ts:952–961](../../packages/backend/convex/notes.ts#L952). A public share must not grant access to unrelated private conversations.
- **Severity / confidence:** Critical / high. No remote exploit or private-data read was attempted.
- **Fix seam:** make the trusted `userId` search primitive internal and update the wrapper reference, or derive and enforce identity inside the public query. Preserve an explicit collaborator-aware conversation access policy rather than trusting filter arguments. Apply limits before expensive work.
- **Acceptance test:** seed two users with messages sharing a search term; call both exported references anonymously and as the other user, including a victim ID obtained from a public share. Neither path may return private rows; legitimate own-user search still works.

#### DS-02 — High: public file actions expose private blobs and cross-user RAG results

- **Evidence / trace:** `extractFileText` is a public action that accepts only `fileId`, uses an internal unrestricted file lookup, reads `file.storageId`, and returns `blob.text()` with no identity or ownership check: [files/chunking.ts:134–170](../../packages/backend/convex/files/chunking.ts#L134). `searchFileChunks` is a public action accepting arbitrary `userId`, pays for an embedding, passes that ID into the internal vector search, and returns hydrated chunks and file records: [files/search.ts:27–106](../../packages/backend/convex/files/search.ts#L27), [files/search.ts:126–166](../../packages/backend/convex/files/search.ts#L126). This bypasses the ownership-protected storage URL API: [storage.ts:9–20](../../packages/backend/convex/storage.ts#L9).
- **Caller evidence:** server tools already intend to call search through `internal.files.search.searchFileChunks`, not expose it to clients: [tools/search/searchFiles.ts:23–33](../../packages/backend/convex/tools/search/searchFiles.ts#L23). The embedding pipeline similarly calls `internal.files.chunking.chunkFile` despite its public declaration: [files/embeddings.ts:69–83](../../packages/backend/convex/files/embeddings.ts#L69), [files/chunking.ts:94–125](../../packages/backend/convex/files/chunking.ts#L94). Treat this as a visibility-contract cleanup; do not claim that an internal reference necessarily fails at runtime without validating Convex dispatch behavior.
- **Impact:** knowledge of a file ID allows anonymous raw-file disclosure; knowledge of an owner ID allows semantic discovery of that owner's indexed file content. File IDs are identifiers, not access grants. Search additionally spends platform embedding credits anonymously.
- **Severity / confidence:** High / high for missing authorization; successful semantic retrieval additionally requires indexed chunks and a configured embedding provider.
- **Fix seam:** make pipeline-only chunking/search/extraction functions internal; expose a separate authenticated wrapper only if a real client needs one. Derive user identity in the wrapper and check file/project ownership before provider calls. Do not repair this by weakening storage URL checks.
- **Acceptance test:** owner/outsider/anonymous matrix for text extraction and file search; wrong-user and wrong-project requests are rejected before any mocked `embed` or storage read. Internal ingestion and chat-tool retrieval remain functional.

#### DS-03 — High: normalized source queries remain anonymously readable

- **Evidence / trace:** all three public source queries read by supplied message/conversation ID without identity or parent authorization: `getSources` returns title, snippet, URL and metadata [sources/operations.ts:89–135](../../packages/backend/convex/sources/operations.ts#L89); `getByConversation` returns source URLs/titles/message IDs [sources/operations.ts:142–160](../../packages/backend/convex/sources/operations.ts#L142); `getSourcesWithFallback` repeats the unrestricted read [sources/operations.ts:168–217](../../packages/backend/convex/sources/operations.ts#L168). They are live UI paths, not only dead utilities: [components/chat/MessageActions.tsx:61](../../apps/web/src/components/chat/MessageActions.tsx#L61), [ConversationHeaderMenu.tsx:81](../../apps/web/src/components/chat/ConversationHeaderMenu.tsx#L81).
- **Impact:** private research snippets, document titles and potentially sensitive URLs leak to anyone possessing a message/conversation ID. The newly secured `batchGetMetadata` route is not an effective boundary while these alternate reads remain public: [security.test.ts:132–155](../../packages/backend/convex/__tests__/security.test.ts#L132).
- **Severity / confidence:** High / high.
- **Fix seam:** use the same parent-conversation authorization helper as the secured message metadata paths before reading any normalized rows. Public-share access should use a separate share-authorized projection, not a general ID-only back door.
- **Acceptance test:** owner and actual collaborator receive sources; anonymous, outsider, revoked participant and deleted-parent cases return no source content across every public alias.

#### DS-04 — High: anonymous, unmetered AI generation outside the chat admission path

- **Evidence / trace:** `summarizeSelection` is a public action whose handler ignores context and calls `generateText` directly, with no authentication, input-size bound, model-policy admission or usage recording: [generation.ts:1975–2020](../../packages/backend/convex/generation.ts#L1975). The note popover invokes it directly: [SummarizePopover.tsx:34–58](../../apps/web/src/components/notes/SummarizePopover.tsx#L34). Public task/meeting extraction also ignores context and calls paid models, then fans out one more model request for each extracted deadline: [ai/taskExtraction.ts:37–85](../../packages/backend/convex/ai/taskExtraction.ts#L37), [ai/taskExtraction.ts:94–125](../../packages/backend/convex/ai/taskExtraction.ts#L94), [ai/meetingExtraction.ts:52–108](../../packages/backend/convex/ai/meetingExtraction.ts#L52), [ai/meetingExtraction.ts:115–157](../../packages/backend/convex/ai/meetingExtraction.ts#L115). Meeting extraction has active callers on the assistant page: [assistant/page.tsx:61–62](../../apps/web/src/app/(main)/assistant/page.tsx#L61).
- **Impact:** anonymous callers can spend provider credits without appearing in per-user usage or being constrained by the chat monthly limit. Deadline fan-out amplifies one request. Next.js auth middleware and REST rate limits do not cover direct Convex public calls.
- **Severity / confidence:** High / high. Actual monetary amount depends on configured providers; no paid calls were made.
- **Fix seam:** create one authenticated auxiliary-AI admission/accounting seam, with transcript/selection and extracted-item bounds, timeout/concurrency limits, budget enforcement and usage on every model call. Pipeline helpers should be internal. Keep operational model/prompt configuration centralized.
- **Acceptance test:** anonymous requests and over-budget users cause zero provider calls; size/fan-out bounds are enforced; success, deadline parsing and failures after a billable response each produce attributable usage exactly once.

#### DS-05 — Medium: conversation share APIs publish full internal records, not a share DTO

- **Evidence / trace:** `getSharedConversation` returns the entire conversation; `getSharedMessages` collects and returns every message in that conversation: [shares.ts:159–199](../../packages/backend/convex/shares.ts#L159). The active schema includes `systemPrompt`, cached prompt fields, memory IDs, internal tree references and incognito scheduler metadata: [schema.ts:106–179](../../packages/backend/convex/schema.ts#L106). The share page subscribes directly to both public queries: [SharePageClient.tsx:96–106](../../apps/web/src/app/share/[shareId]/SharePageClient.tsx#L96). By contrast public notes deliberately select public-safe fields: [notes.ts:952–961](../../packages/backend/convex/notes.ts#L952).
- **Impact:** a shared chat discloses conversation-level instructions and any persisted internal fields, plus inactive/edited branches. UI hiding does not remove fields from the network response. Presence of cached prompts in current records was not verified; their disclosure is conditional, not asserted.
- **Severity / confidence:** Medium / high for overbroad response; intended branch-sharing semantics need product confirmation.
- **Fix seam:** explicit allowlisted share projection; define whether sharing means a snapshot, current active path or whole tree. Exclude instructions/private operational state. Keep revocation/expiry checks server-side. Anonymization must be applied to the projection rather than merely storing a flag.
- **Acceptance test:** seed private prompt fields and inactive sibling text, create a share, inspect the anonymous API response (not only rendered DOM), and assert only the approved public schema/path survives. Verify revoked, expired and protected shares fail closed.

### Inferences

- The most effective modernization boundary is a shared authorization/admission layer with thin public wrappers and internal trusted primitives. DS-01–04 demonstrate alternate entrypoints circumventing otherwise-correct wrappers; replacing frameworks would not itself repair that issue. Evidence: [search/hybrid.ts:28–58](../../packages/backend/convex/search/hybrid.ts#L28), [files/search.ts:27–42](../../packages/backend/convex/files/search.ts#L27), [chat.ts:133–157](../../packages/backend/convex/chat.ts#L133).
- Public share identifiers and owner IDs are not secrets that can safely compensate for omitted authorization. The checkout itself intentionally returns them: [shares.ts:147–155](../../packages/backend/convex/shares.ts#L147).

### Gaps

- No runtime deployment, credentials, personal files or provider calls were inspected. Exploitability findings establish code-level trust-boundary failures, not production incident history.
- File search requires existing indexed content and an available embedding service. Tests should mock embeddings, not purchase live inference.
- Prompt-injection resistance cannot be proved by source review. Tool-output boundary markers are useful model guidance, not a security boundary; destructive external tool actions still need authorization in their implementation: [generation/tools.ts:331–360](../../packages/backend/convex/generation/tools.ts#L331).

## Do deletion, caching and credential flows meet their privacy promises?

### Takeaway

Keep the per-account cache partitioning, owned uploads, credential encryption and hardened share/password behavior. The remaining lifecycle problem is divergent deletion implementations: incognito and CLI deletion bypass the fuller cascade, and deleted conversations can leave local message/metadata data behind.

### Cited Findings

#### DS-06 — High: incognito deletion leaves normalized private content behind

- **Evidence / trace:** `executeDelete` manually deletes bookmarks/shares/project junctions/messages/conversation and nullifies files/memories, but never deletes attachments, tool calls, sources, canvas history/documents or integration selections: [incognito.ts:65–165](../../packages/backend/convex/incognito.ts#L65). The shared cascade explicitly handles many of those tables: [lib/utils/cascade.ts:22–145](../../packages/backend/convex/lib/utils/cascade.ts#L22). Incognito cleanup is scheduled hourly for chats inactive more than 24 hours: [crons.ts:46–52](../../packages/backend/convex/crons.ts#L46), [incognito.ts:205–250](../../packages/backend/convex/incognito.ts#L205).
- **Impact:** expiration removes the visible chat while retaining private attachment/extracted-text and tool-output/source records. DS-03 can expose retained sources by old parent ID. File nullification also preserves uploaded blobs instead of making an incognito-specific retention decision. Not every listed child type can be created in incognito today—write tools are intentionally disabled—but attachments and sources are normal generation outputs: [generation.ts:1391–1406](../../packages/backend/convex/generation.ts#L1391), [generation.ts:1423–1447](../../packages/backend/convex/generation.ts#L1423).
- **Severity / confidence:** High / high for retained normalized records; exact blob-retention product policy needs confirmation.
- **Fix seam:** route incognito expiration through the central cascade with an explicit ephemeral-file policy and reference-safe blob cleanup. Do not blindly delete blobs copied to another user's fork. Include generation locks/scheduled work and an erasure tombstone so late actions cannot recreate private rows.
- **Acceptance test:** create an incognito chat containing attachments with extracted text, tool output and sources; run expiry; assert absence of all child rows and unshared blobs, retained shared blobs only where another authorized parent references them, and no recreation by a delayed worker.

#### DS-07 — Medium: CLI hard deletion has a different, incomplete cascade

- **Evidence / trace:** `cliAuth.deleteConversation` verifies owner, deletes only messages and the conversation, leaving all other dependents: [cliAuth.ts:507–537](../../packages/backend/convex/cliAuth.ts#L507). This is reachable from the CLI RPC route: [api/v1/cli/rpc/route.ts:153–158](../../apps/web/src/app/api/v1/cli/rpc/route.ts#L153), and the CLI mutation helper: [apps/cli/src/lib/mutations.ts:60–65](../../apps/cli/src/lib/mutations.ts#L60). The regular web mutation calls `cascadeDeleteConversation`: [conversations.ts:305–313](../../packages/backend/convex/conversations.ts#L305).
- **Impact:** the same delete command leaves shares, bookmarks, metadata, project links and independent file references in different states depending on the client. Orphaned source rows remain readable through DS-03.
- **Severity / confidence:** Medium / high.
- **Fix seam:** invoke the same domain deletion helper from CLI and web after their distinct authentication checks. Preserve the helper's intentional keep/nullify policy for independent files/memories; centralization should not silently become more destructive.
- **Acceptance test:** parameterize one fixture over web/REST/CLI delete paths and compare all remaining records and file access. Invalid/revoked API keys must not delete anything.

#### DS-08 — Medium: conversation disappearance does not cascade local message-cache erasure

- **Evidence / trace:** the chat page unconditionally uses the message-cache hook, including incognito chats: [chat/[conversationId]/page.tsx:37–89](../../apps/web/src/app/(main)/chat/[conversationId]/page.tsx#L37). `useMessageCacheSync` persists the full returned tree without an incognito exclusion: [useCacheSync.ts:198–215](../../apps/web/src/hooks/useCacheSync.ts#L198), [cache/messageTree.ts:91–124](../../apps/web/src/lib/cache/messageTree.ts#L91). Conversation-list reconciliation deletes orphaned **conversation rows only**: [useCacheSync.ts:405–413](../../apps/web/src/hooks/useCacheSync.ts#L405). Message removal requires a mounted subscription returning an authoritative empty tree. Startup cleanup retains messages up to 30 days and only runs on app start: [cache/cleanup.ts:3–35](../../apps/web/src/lib/cache/cleanup.ts#L3).
- **Impact:** a chat deleted or expired while its detail view is unmounted can leave its cached messages, attachments, tool outputs and sources on disk. Account partitioning prevents accidental cross-account UI reads, but it is not deletion or an incognito retention policy.
- **Severity / confidence:** Medium / high for retained data path. No claim that another account can access it through the hardened UI.
- **Fix seam:** do not persist incognito content to durable IndexedDB, or explicitly document and implement a bounded ephemeral store. On authoritative conversation deletion, transactionally purge associated messages and metadata even when the detail hook is unmounted. Distinguish deletion from temporary list filtering/project changes so archive/filter operations do not erase unrelated offline data.
- **Acceptance test:** cache an incognito chat, navigate away, expire/delete it, refresh and inspect all IndexedDB tables. Repeat deletion from a second client while the first client is offline, then reconnect. Ensure ordinary filtering does not masquerade as an erasure event.

#### Keep: existing protections worth preserving

- **JWT-derived identity and ownership/collaboration checks:** the legacy Clerk-ID argument now only checks a match against the authenticated user; the caller cannot impersonate an arbitrary Clerk ID: [conversations.ts:136–155](../../packages/backend/convex/conversations.ts#L136). Dedicated adversarial tests already cover anonymous/outsider/owner/collaborator cases: [security.test.ts:97–129](../../packages/backend/convex/__tests__/security.test.ts#L97).
- **Owned upload registration and bounded storage writes:** upload token verification precedes bounded body reading/storage and internal ownership registration; rejected uploads delete the new blob: [http.ts:28–65](../../packages/backend/convex/http.ts#L28). `storage.getUrl` resolves owned files only: [storage.ts:9–20](../../packages/backend/convex/storage.ts#L9).
- **Fail-closed protected sharing:** public conversation queries deny password-bearing shares; `verify` explicitly refuses to pretend that a client boolean is an authorization grant: [shares.ts:167–189](../../packages/backend/convex/shares.ts#L167), [shares.ts:223–227](../../packages/backend/convex/shares.ts#L223). Public notes similarly deny password-bearing records: [notes.ts:941–950](../../packages/backend/convex/notes.ts#L941). This is a disabled feature, not a password-bypass vulnerability.
- **Per-account/per-deployment local cache:** database names include both deployment and user; legacy unowned caches are not opened, and consumers remount when Clerk/Convex identity changes: [cache/db.ts:28–37](../../apps/web/src/lib/cache/db.ts#L28), [cache-provider.tsx:13–40](../../apps/web/src/components/providers/cache-provider.tsx#L13). Metadata writes have explicit request scope and stale-identity fencing: [cache/messageTree.ts:22–85](../../apps/web/src/lib/cache/messageTree.ts#L22). Do not regress these protections in pursuit of one global cache.
- **Credential handling:** BYOK public configuration returns presence booleans, not ciphertext/plaintext; full credentials are internal-only: [byok/credentials.ts:17–53](../../packages/backend/convex/byok/credentials.ts#L17), [byok/credentials.ts:181–188](../../packages/backend/convex/byok/credentials.ts#L181). Encryption uses randomized IVs and authenticated AES-256-GCM: [lib/encryption.ts:21–51](../../packages/backend/convex/lib/encryption.ts#L21). BYOD config likewise excludes encrypted credentials: [byod/credentials.ts:16–48](../../packages/backend/convex/byod/credentials.ts#L16).
- **Account erasure has a real central implementation:** account deletion calls `cascadeDeleteUserData`; it enumerates owned conversations, normalized junctions/content/config and reference-checks blobs instead of deleting other users' shared files indiscriminately: [users.ts:98–113](../../packages/backend/convex/users.ts#L98), [lib/utils/cascade.ts:155–204](../../packages/backend/convex/lib/utils/cascade.ts#L155), [lib/utils/cascade.ts:488–500](../../packages/backend/convex/lib/utils/cascade.ts#L488). Large-account batching and external backup retention were not runtime-tested.

### Inferences

- Incognito should be treated as an end-to-end data-lifecycle capability, not just a tool-availability flag or timer. The backend already disables persistent write tools and external integrations, but its deletion and durable browser cache do not implement the same retention boundary: [generation/tools.ts:175–218](../../packages/backend/convex/generation/tools.ts#L175), [generation/tools.ts:277–295](../../packages/backend/convex/generation/tools.ts#L277), [incognito.ts:80–160](../../packages/backend/convex/incognito.ts#L80), [useCacheSync.ts:198–215](../../apps/web/src/hooks/useCacheSync.ts#L198).

### Gaps

- This review did not verify erasure from Convex backups, third-party provider retention, old Postgres rollback stores or private restore snapshots. The runbook explicitly retains the old stores/snapshot/mapping tables until later coordinator approval: [restore-postgres-to-convex.md:242–243](../../docs/migrations/restore-postgres-to-convex.md#L242). Do not claim that application deletion is universal historical-data erasure.
- BYOD public settings and routing helpers exist, but successful request-wide routing to a user's instance was not established. REST authenticated clients visibly target the platform URL, while separate BYOD helpers are not themselves authenticated clients: [api/convex.ts:24–31](../../apps/web/src/lib/api/convex.ts#L24), [api/convex.ts:50–78](../../apps/web/src/lib/api/convex.ts#L50). Treat the BYOD privacy promise as an explicit acceptance gate, not a verified capability; test both WebSocket and HTTP clients against two deployments before advertising it.

## Are payer selection, accounting, API contracts and operations dependable?

### Takeaway

There are concrete payer/accounting defects, not merely missing enterprise billing infrastructure: ordinary chat ignores enabled BYOK, stop paths omit incurred usage, and daily aggregation loses dimensions. The most direct cross-client regression is the REST conversation DAL sending an argument the Convex query does not accept.

### Cited Findings

#### DS-09 — High: enabled BYOK does not affect ordinary chat provider selection

- **Evidence / trace:** the settings UI tells users “All AI requests use your API keys” when enabled: [BYOKSettings.tsx:332–336](../../apps/web/src/components/settings/BYOKSettings.tsx#L332). Ordinary chat resolves a model with `getModel(modelId)` and uses attribution-only gateway options: [generation.ts:639–653](../../packages/backend/convex/generation.ts#L639). `getModel` selects prebuilt module-level clients with no user-key parameter/config lookup: [packages/ai/src/registry.ts:43–91](../../packages/ai/src/registry.ts#L43). Those clients use environment credentials: [providers/gateway.ts:1–6](../../packages/ai/src/providers/gateway.ts#L1), [providers/groq.ts:1–5](../../packages/ai/src/providers/groq.ts#L1). Gateway options contain user/tags/order, not credentials: [packages/ai/src/gateway.ts:23–40](../../packages/ai/src/gateway.ts#L23). Chat completion also never passes `isByok` into the usage recorder: [messages.ts:860–883](../../packages/backend/convex/messages.ts#L860).
- **Impact:** a user can successfully enable BYOK while ordinary chat continues billing the platform's provider account (or fails for missing platform credentials despite their configured key), and records do not identify it as BYOK. This is both a cost and user-trust issue.
- **Severity / confidence:** High / high for ordinary text-chat path. This does not claim all speech/image paths ignore BYOK.
- **Fix seam:** request-scoped provider factory accepting a resolved payer/credential context, derived server-side from the initiating user. Never mutate singleton SDK credentials per request. Explicitly decide missing-key behavior; no silent platform fallback in BYOK mode. Propagate payer and `isByok` through completion/accounting and auxiliary model calls.
- **Acceptance test:** two concurrent users with distinct synthetic provider keys hit isolated mocked clients; BYOK request never uses platform credentials, missing/decryption-failed keys reject before inference, non-BYOK still uses platform credentials, and each ledger entry identifies its actual payer.

#### DS-10 — High: stopping text generation drops incurred usage from the budget ledger

- **Evidence / trace:** the streaming action exits immediately when its abort signal is set, before final usage calculation: [generation.ts:1035–1043](../../packages/backend/convex/generation.ts#L1035). Its catch path also returns for stopped messages or `AbortError`: [generation.ts:1574–1596](../../packages/backend/convex/generation.ts#L1574). A late final status check skips `completeMessage` for stopped rows: [generation.ts:1451–1472](../../packages/backend/convex/generation.ts#L1451). Even when called for a terminal row, `completeMessage` only records usage for **images**, not text: [messages.ts:812–841](../../packages/backend/convex/messages.ts#L812). Monthly admission sums `usageRecords`: [lib/monthlyBudget.ts:6–20](../../packages/backend/convex/lib/monthlyBudget.ts#L6), [chat.ts:144–157](../../packages/backend/convex/chat.ts#L144).
- **Impact:** provider-billable input/output from stopped responses is missing from spend and hard-limit enforcement. Repeatedly stopping just before completion can accumulate real costs without advancing the recorded budget. Failed-stream “wasted cost” is calculated for error telemetry, not recorded usage: [generation.ts:1637–1666](../../packages/backend/convex/generation.ts#L1637).
- **Severity / confidence:** High / high for accounting omission; exact provider billing on abort varies.
- **Fix seam:** finalize accounting independently of user-visible message status. Persist provider usage when available, otherwise a clearly labeled estimate with later reconciliation. Use a generation/attempt idempotency key so stop/completion/recovery cannot double count. Preserve stopped content/status.
- **Acceptance test:** provider mock emits partial tokens then is stopped/throws/finishes after a stop race; every billable attempt is charged once, message remains stopped, and subsequent budget admission sees the spend.

#### DS-11 — Medium: daily usage upsert loses conversation, feature and payer dimensions

- **Evidence / trace:** `recordTextGeneration` looks up the first row by user/date/model and updates only token/cost/message totals; `conversationId`, `feature` and `isByok` come from the first insert and never change: [usage/mutations.ts:76–123](../../packages/backend/convex/usage/mutations.ts#L76). `getConversationCosts` groups by the retained conversation ID, while `getUsageSummary` filters by `isByok`: [usage/queries.ts:145–185](../../packages/backend/convex/usage/queries.ts#L145), [usage/queries.ts:209–255](../../packages/backend/convex/usage/queries.ts#L209). Request counts also count rows rather than aggregated `messageCount`: [usage/queries.ts:81–90](../../packages/backend/convex/usage/queries.ts#L81), [usage/queries.ts:234–254](../../packages/backend/convex/usage/queries.ts#L234).
- **Impact:** same-day same-model requests in different chats/features are attributed to the first chat/feature; switching payer mode yields incorrect BYOK/platform breakdown. Daily cost totals can still be correct, so avoid describing all accounting as lost. Request averages/counts become misleading after aggregation.
- **Severity / confidence:** Medium / high.
- **Fix seam:** immutable per-attempt ledger plus derived daily aggregates, or an aggregate key that includes all required dimensions. Keep identity, payer, operation, feature, conversation, actual/estimated usage and idempotency explicit. Migrate existing aggregates honestly; lost attribution cannot be reconstructed from the aggregate alone.
- **Acceptance test:** interleave two conversations, two features and payer modes on the same day/model; totals, request counts and filtered breakdowns match the fixture exactly. Replaying an attempt does not increase spend twice.

#### DS-12 — Medium: REST conversation listing passes an unsupported Convex argument

- **Evidence / trace:** `/api/v1/conversations` always computes an `archived` boolean and passes it to the DAL: [conversations/route.ts:49–59](../../apps/web/src/app/api/v1/conversations/route.ts#L49). The DAL always sends `{ limit, archived, projectId }` to `api.conversations.list`: [dal/conversations.ts:87–108](../../apps/web/src/lib/api/dal/conversations.ts#L87). The target validator accepts only `searchQuery`, `limit` and `projectId`, and its default implementation explicitly excludes archived records: [convex/conversations.ts:159–164](../../packages/backend/convex/conversations.ts#L159), [convex/conversations.ts:198–202](../../packages/backend/convex/conversations.ts#L198). The shared SDK uses this REST route: [api-client/src/client.ts:133–150](../../packages/api-client/src/client.ts#L133).
- **Impact:** runtime argument validation rejects even the normal `archived=false` list request; HTTP/mobile clients fail while direct Convex clients work. Simply dropping the argument would still leave `archived=true` behavior unimplemented.
- **Severity / confidence:** Medium / high; no live call performed.
- **Fix seam:** align the public query validator and archive semantics with the REST/SDK contract; add one shared request contract where practical, then regenerate OpenAPI. Do not add `any` to hide the mismatch.
- **Acceptance test:** actual route plus real Convex validator (not a permissive DAL mock), normal/archived/project/none queries, invalid IDs and limits, authenticated outsider. Assert HTTP envelope and SDK-parsed results.

#### DS-13 — Medium: vector search results are cast to message documents without hydration

- **Evidence / trace:** hybrid search treats `ctx.vectorSearch` results as full messages, removes `_score` and casts the remaining object to `Doc<"messages">`, then filters by message timestamps/role and RRF-merges it: [search/hybrid.ts:86–121](../../packages/backend/convex/search/hybrid.ts#L86). The file-vector implementation demonstrates the necessary hydration pattern: fetch each result `_id` through a query before accessing content/embedding: [files/search.ts:136–148](../../packages/backend/convex/files/search.ts#L136).
- **Impact:** when hybrid mode is enabled, vector-only hits can lack message content/role/date; filters can drop them or downstream display receives incomplete records. The cast hides the contract mismatch. Text-only mode can mask it.
- **Severity / confidence:** Medium / high by Convex vector result contract; exact visible behavior depends on merge/output consumers and admin flag.
- **Fix seam:** hydrate result IDs in an internal authorized batch query, retain `_score` separately, validate ownership and order, and merge real documents. Avoid per-hit unbounded reads.
- **Acceptance test:** mock vector results with realistic `{ _id, _score }` only, seed a semantically matching message absent from full-text hits, and verify complete authorized results with role/date filters and deduplication. Deleted hits are skipped safely.

#### DS-14 — Low: OAuth callback logging defeats otherwise careful state handling

- **Evidence / trace:** the callback logs `Object.fromEntries(searchParams.entries())` wholesale, including state and any provider-returned query values: [composio/callback/route.ts:25–27](../../apps/web/src/app/api/composio/callback/route.ts#L25). Pino redaction names token/key/secret/password paths, not `params.state` or arbitrary `params.code`: [lib/logger.ts:3–22](../../apps/web/src/lib/logger.ts#L3). OAuth initiation generates a random state and stores it for validation: [composio/oauth.ts:146–175](../../packages/backend/convex/composio/oauth.ts#L146); verification checks current user, connection owner, state and expiration: [composio/oauth.ts:196–251](../../packages/backend/convex/composio/oauth.ts#L196).
- **Impact:** a live anti-CSRF state is copied into operational logs; a future callback carrying an authorization code would be logged too. This is not evidence of an account-takeover path—the owner check and session binding still matter.
- **Severity / confidence:** Low / high for state logging; actual returned code parameters were not observed.
- **Fix seam:** allowlist parameter names/counts, connection ID and `hasState`, never query values. Redact sensitive URL query fields centrally as defense in depth.
- **Acceptance test:** callback request with synthetic state/code/access token; logger sink contains none of their values while still providing request ID, outcome and safe connection metadata.

### Inferences

- Prefer narrow modernization seams: public authenticated wrappers, internal trusted primitives, one conversation-erasure implementation, one request-scoped payer resolver and a dimensionally correct usage ledger. These directly address the traced failures without replacing working durable generation, Convex subscriptions or identity-partitioned caches. Sources: [chat.ts:133–157](../../packages/backend/convex/chat.ts#L133), [lib/utils/cascade.ts:14–20](../../packages/backend/convex/lib/utils/cascade.ts#L14), [usage/mutations.ts:92–123](../../packages/backend/convex/usage/mutations.ts#L92), [registry.ts:43–91](../../packages/ai/src/registry.ts#L43).
- Prioritization: block DS-01–04 first; then payer correctness and incurred-cost accounting (DS-09–10), privacy erasure (DS-06–08), client/runtime contracts (DS-12–13), and attribution/projection/logging cleanup (DS-05, DS-11, DS-14). This ordering is an impact-based recommendation, not measured exploit frequency.

### Gaps

- No Stripe/payment webhook implementation was found in the reviewed active Convex/Next API surface; the webhook reviewed here is Clerk identity synchronization. Do not invent a payment-webhook defect or demand enterprise billing infrastructure. Establish intended monetization separately before designing payments.
- No installs, application edits, builds, heavy checks, live auth reads, external mutations, fetches or provider calls were performed. Suggested tests above are acceptance criteria, not test-pass claims. Existing tracked/untracked user work was preserved; this research note is the only file written.
- Exact deployment headers, edge rate limits, provider charges, database scale and all client journeys remain unverified. Static source review is strongest on explicit trust boundaries and incompatible contracts; it is not a launch certification.
