# Frontend, chat rendering, performance, and accessibility

## 1. What is shipped, and how does the chat UI work?

### Takeaway

The current frontend already has most of the building blocks a modernization proposal might otherwise introduce: React 19/Next 16, Streamdown, Shiki, lazy Mermaid and Monaco, real-time durable-message reads, local IndexedDB state, optimistic sends, virtualized history, motion preferences, and accessibility settings. The opportunity is to make these paths agree and prove their behavior, rather than replace the stack wholesale. #### Streaming, markdown, code, math, Mermaid, citations and artifacts

- Rendered message text prefers persisted `partialContent` to `content`; `pending`/`generating` determines streaming. Tool calls come from normalized cached rows and are converted to the renderer's `name`/stringified-arguments shape. Inline tool positions split the answer into independently rendered markdown segments; streaming tool activity is shown in the status timeline, while completed tool panels appear inline. - The streaming/small-answer path normalizes LaTeX delimiters, regex-linkifies numbered citations and Bible verses, then reveals buffered words at 30 words/second. Reduced-motion users bypass that buffer. Streamdown handles incomplete markdown, with custom code, image and link components; rehype raw/hardening and an explicit protocol check are configured. This is already a streaming-aware markdown renderer, not a naive token-by-token ReactMarkdown implementation. Highlighting is scheduled with `requestIdleCallback`, or a Safari timeout; the code shell has copy/wrap controls and a 600px vertical limit. This is scheduled main-thread work, not worker highlighting during streaming. A 200-entry, five-minute LRU caches the result; unavailable/failed workers fall back to Streamdown. ### Inferences

- There are two rendering products under one component name: interactive React markdown and static completed-answer HTML. Their semantics, supported grammars, chemistry, controls and link handling must be treated as a shared contract before optimizing either independently. The current branch switch makes answer length and tool segmentation affect capabilities. [Branch switch](../../apps/web/src/components/chat/MarkdownContent.tsx#L354-L434), [segment-level renderer](../../apps/web/src/components/chat/InlineToolCallContent.tsx#L165-L185).
- The durable server action boundary should remain untouched by a frontend refresh: the current UI consumes persisted status/content rather than depending on a browser-owned stream. This aligns with the repository's refresh-survival rule. [Instructions](../../AGENTS.md#L21-L26), [display selection](../../apps/web/src/components/chat/ChatMessage.tsx#L145-L187), [subscription](../../apps/web/src/hooks/useCacheSync.ts#L198-L215).

## 2. Which defects and maintenance costs deserve attention first?

### Takeaway

The strongest static findings concern lost capabilities and misleading state: normalized artifact records cannot match the artifact extractor; long completed answers lose React controls; source links have no target contract; failed optimistic sends have no rollback. Accessibility and history navigation also contain concrete mismatches that deserve deterministic regression tests before visual polish. [Artifacts](../../apps/web/src/components/chat/ArtifactList.tsx#L23-L55), [HTML branch](../../apps/web/src/components/chat/MarkdownContent.tsx#L388-L397), [source markup](../../apps/web/src/components/chat/SourceList.tsx#L71-L83), [mutation failure](../../apps/web/src/lib/hooks/mutations/useSendMessage.ts#L142-L174).

### Cited Findings

All findings below are **static code findings**, not browser-reproduced failures. “Important” means material task/reliability/accessibility impact; no unverified critical incident is asserted.

1. **Important — Document artifact extraction uses the old data shape. High confidence.** `useCachedToolCalls` returns `Doc<"toolCalls">[]`, persisted unchanged by metadata sync. Those rows have `toolName`, `args`, native JSON `result`, and `_id`/`toolCallId`. `ArtifactList` instead filters `tc.name`, parses `tc.result` as JSON text and reads `tc.arguments`/`tc.id`. Thus normalized `createDocument`/`updateDocument` rows fail the name filter before a card can appear. `ChatMessage` already contains the correct adapter for its other tool renderer. **Repair:** use typed normalized rows directly or one shared adapter; remove `any`; test a real schema-shaped successful document result and a partial/error result. [Schema:453-469](../../packages/backend/convex/schema.ts#L453-L469), [cached hook:591-597](../../apps/web/src/hooks/useCacheSync.ts#L591-L597), [raw persistence:52-83](../../apps/web/src/lib/cache/messageTree.ts#L52-L83), [broken consumer:26-54](../../apps/web/src/components/chat/ArtifactList.tsx#L26-L54), [existing adapter:239-250](../../apps/web/src/components/chat/ChatMessage.tsx#L239-L250).

2. **Important — Long completed answers lose code controls, Mermaid rendering and Bible popovers. High confidence.** At 5,000 code units the worker replaces the entire React subtree with `dangerouslySetInnerHTML`. Worker code emits only a code wrapper; Mermaid emits a `mermaid-placeholder`; Bible links are bare `bible://` anchors. No hydration/enhancement consumer for those placeholder classes/data attributes was found in `apps/web/src`; the mounted hooks only enhance math. The controls and component callbacks therefore cannot carry over into this branch. Long messages also initially take the Streamdown path while the worker runs, so parsing work is not completely removed from the main thread. **Repair:** preserve a common AST/block/component contract, offloading parsing/highlighting rather than replacing the interactive layer, or limit the worker path to genuinely static content until parity exists. Test below/at/above the threshold, completion, edits, and worker failure with identical content. [Threshold:76-105](../../apps/web/src/hooks/useWorkerMarkdown.ts#L76-L105), [branch/hooks:354-434](../../apps/web/src/components/chat/MarkdownContent.tsx#L354-L434), [worker code/links:256-311](../../apps/web/src/lib/markdown/worker.ts#L256-L311).

3. **Important — Numbered citations cannot navigate to sources. High confidence.** Citation clicks prevent default then query global `#source-N`; the source cards never assign those IDs and are unmounted until expanded. Even adding unscoped IDs would collide across messages. The toggle has no `aria-expanded`/`aria-controls`. **Repair:** scope source IDs by message, open the source section before navigating, then focus the matching source link; test two messages each citing `[1]`, collapsed sources, keyboard activation and virtualized history. [Click handler:180-198](../../apps/web/src/components/chat/MarkdownContent.tsx#L180-L198), [collapsed grid:40-83](../../apps/web/src/components/chat/SourceList.tsx#L40-L83), [source card:105-162](../../apps/web/src/components/chat/SourceList.tsx#L105-L162).

4. **Important — Failed sends can leave a phantom sent-looking user message. High confidence.** `onMutate` appends an optimistic message, but `onError` only toasts/queues it; there is no remove/update callback. Reconciliation appends every unmatched optimistic row and intentionally retains optimistic state. An online rejected send therefore has no explicit failed/unsent state or rollback. In addition, if a server row has a nonmatching client ID, matching still falls through to nearest timestamp without content or conversation checks; retaining old optimistics makes false matches/reappearance after server deletion or branch changes plausible. **Repair:** track pending/sent/failed by explicit client ID and conversation, remove acknowledged entries, preserve retryable failed drafts, and never fuzzy-match conflicting IDs. [Mutation:91-123](../../apps/web/src/lib/hooks/mutations/useSendMessage.ts#L91-L123), [error:142-174](../../apps/web/src/lib/hooks/mutations/useSendMessage.ts#L142-L174), [fallback matching:144-179](../../apps/web/src/hooks/useOptimisticMessages.ts#L144-L179), [unmatched merge:182-207](../../apps/web/src/hooks/useOptimisticMessages.ts#L182-L207), [retention:243-282](../../apps/web/src/hooks/useOptimisticMessages.ts#L243-L282).

5. **Important — History's infinite-load sentinel is outside the scrolling history. High confidence about placement; runtime consequence unverified.** The observer has no `root`, while its target is a sibling above `VirtualizedMessageList`, not an element inside either history scroller. Its visibility is therefore unrelated to scrolling to the oldest loaded message; it may eagerly load page after page while that fixed sibling remains visible. **Repair:** use Virtuoso's start-reached path and a sentinel inside the ordinary scroller, preserving the visible message anchor while prepending. Keep the explicit “Load older messages” fallback. [Observer:324-342](../../apps/web/src/app/(main)/chat/[conversationId]/page.tsx#L324-L342), [placement:492-549](../../apps/web/src/app/(main)/chat/[conversationId]/page.tsx#L492-L549), [actual scroller:260-294](../../apps/web/src/components/chat/VirtualizedMessageList.tsx#L260-L294).

6. **Important — Keyboard focus colors use incompatible token syntax. High confidence.** Tokens such as `--ring`, `--primary` and `--background` contain complete `oklch(...)` colors. Global focus outlines and message-group outlines wrap them in `hsl(var(...))`, producing invalid nested color syntax. Skip-link, highlight and some prose/legacy code styles repeat this pattern; `oklch(var(--background))` is likewise incompatible with a complete color value. Components using valid Tailwind rings can still show focus, so this is not a claim that all focus is invisible. **Repair:** use `var(--ring)`/`var(--primary)` consistently and lint color-token consumption; verify plain native controls, j/k-focused groups and forced-colors mode. [Tokens:58-81](../../apps/web/src/app/globals.css#L58-L81), [dark ring:180-201](../../apps/web/src/app/globals.css#L180-L201), [focus:373-409](../../apps/web/src/app/globals.css#L373-L409), [background:566-571](../../apps/web/src/app/globals.css#L566-L571), [cursor:391-399](../../apps/web/src/styles/prose.css#L391-L399), [legacy code:1-9](../../apps/web/src/styles/code-theme.css#L1-L9).

7. **Important — Native selection is cleared for short and cross-message selections. High confidence.** Desktop mouseup calls `clearSelection()` for fewer than ten characters or when the range's common ancestor is outside one `.chat-message`. `clearSelection()` invokes `removeAllRanges()`, so “do not show custom menu” also means “erase the user's native selection.” Copying an identifier or selecting across turns is affected by construction. The scroll cleanup checks `.chat-message-list`, while the actual history uses `.messages-container`/a Virtuoso wrapper, so the custom menu may also outlive scrolling. **Repair:** separate menu dismissal from clearing native selection; preserve all native selections; use the actual scroll root; support keyboard selection without requiring mouseup. Mobile already deliberately keeps native selection. [Selection clearing:45-71](../../apps/web/src/contexts/SelectionContext.tsx#L45-L71), [short/cross-message paths:90-128](../../apps/web/src/contexts/SelectionContext.tsx#L90-L128), [scroll check:190-197](../../apps/web/src/contexts/SelectionContext.tsx#L190-L197), [history classes](../../apps/web/src/components/chat/VirtualizedMessageList.tsx#L260-L270).

8. **Important — Code wrapping is a no-op; code controls are hover-only. High confidence.** The wrap state only changes the icon and label inside `ClientCodeControls`; it is never returned to `CodeBlock` and changes no whitespace style. Both 24px controls remain `opacity-0` except on `group-hover`, with no focus-visible/focus-within or touch visibility rule. Copy rejects are not caught. **Repair:** lift wrap state to the code shell, apply `white-space`/overflow deliberately, reveal controls on keyboard focus and coarse-pointer devices, and announce copy success/failure. Cover a long unbroken line and a denied clipboard. [Controls:7-44](../../apps/web/src/components/chat/ClientCodeControls.tsx#L7-L44), [shell:97-115](../../apps/web/src/components/chat/CodeBlock.tsx#L97-L115).

9. **Important — Completion announcements miss the normal generating-to-complete transition. High confidence about hook logic.** `useMessageAnnouncer` records the assistant ID/count while it is generating, but only announces if that ID/count subsequently changes. Completion of the same row changes neither, so its intended completion announcement is skipped. The history also has a live log and messages contain separate live status nodes; those may announce something, but they do not establish predictable, nonduplicated screen-reader output. **Repair:** track per-message status transitions and announce once at completion, with one clear owner for live output. Never reread loaded history on pagination/conversation change. [Announcer:59-91](../../apps/web/src/hooks/useMessageAnnouncer.ts#L59-L91), [live log](../../apps/web/src/components/chat/VirtualizedMessageList.tsx#L265-L270), [per-message status](../../apps/web/src/components/chat/ChatMessage.tsx#L480-L519).

10. **Important — Math copy/accessibility enhancement is not tied to asynchronously appearing math. High confidence about dependencies.** Copy enhancement runs only on the stable `containerRef`; semantic enhancement runs on that ref plus `isStreaming`. Math arriving later through buffer updates, mobile skeleton replacement or worker HTML can therefore miss enhancements. Both retain sets of processed DOM elements; repeated replacements can retain detached nodes until unmount. The copy hook also gives nested `.katex` elements `role=button` before the accessibility hook changes them to `role=math`. **Repair:** enhance a stable rendered-block lifecycle, or use a narrowly scoped observer with cleanup; avoid imperative wrapping inside React-owned trees where possible; expose a separate real copy button while preserving math semantics. [Copy scan/dependency:58-152](../../apps/web/src/hooks/useMathCopyButtons.ts#L58-L152), [semantic scan/dependency:21-102](../../apps/web/src/hooks/useMathAccessibility.ts#L21-L102), [async branches:379-397](../../apps/web/src/components/chat/MarkdownContent.tsx#L379-L397).

11. **Important — Scroll behavior diverges between ordinary and virtualized lists. Static integration risk.** The ordinary path has initial positioning, explicit jump, highlight and composer-resize scrolling, but no explicit content-growth/new-message follow effect. Native `overflow-anchor` is enabled, but it is not a complete documented follow contract. The virtualized path always returns `"smooth"` from `followOutput`, ignoring the reduced-motion value used elsewhere. Intent only recognizes pointer/touch/wheel, not keyboard-driven upward navigation. Both intent and restoration effects depend on the ref object, not the underlying DOM scroller, so crossing the 500-group threshold can leave listeners on the old element. **Repair:** one tested near-bottom/reading/selection state machine, keyboard-aware escape, element-aware listener binding, and reduced-motion-safe follow output. Measure rather than simply lowering the virtualization threshold. [Ordinary scroll:128-249](../../apps/web/src/components/chat/VirtualizedMessageList.tsx#L128-L249), [virtual follow:334-344](../../apps/web/src/components/chat/VirtualizedMessageList.tsx#L334-L344), [intent dependencies:28-125](../../apps/web/src/hooks/useScrollIntent.ts#L28-L125), [restoration binding:77-109](../../apps/web/src/hooks/useScrollRestoration.ts#L77-L109), [CSS anchoring](../../apps/web/src/app/globals.css#L529-L545).

12. **Important — Keyboard navigation and message actions disagree about focus ownership. High confidence about DOM targets.** j/k focuses the outer `message-group-N`, but `ChatMessage` only sets `isFocused` from its inner article's focus events. Focusing an ancestor does not focus that descendant, so advertised per-message r/b/c/delete shortcuts are not activated by that navigation alone. The global navigation handler also intercepts arrow keys on buttons, links and non-input widgets, including outside the chat, because it only excludes input/textarea/direct contenteditable targets. The ordinary path hardcodes smooth scrolling; the virtual path tries focus after a single animation frame, before an offscreen row is guaranteed mounted. **Repair:** scope shortcuts to the transcript, focus the actual message action owner, exclude composite widgets/dialogs, and use a row-mount-aware focus callback. [Navigation:40-69](../../apps/web/src/hooks/useMessageNavigation.ts#L40-L69), [global interception:105-170](../../apps/web/src/hooks/useMessageNavigation.ts#L105-L170), [article focus](../../apps/web/src/components/chat/ChatMessage.tsx#L344-L359), [shortcut enablement](../../apps/web/src/hooks/useMessageKeyboardShortcuts.ts#L45-L61).

13. **Important — Canvas has no mobile surface in the inspected conversation route. High confidence.** The only route canvas panel is gated by `documentId && !isMobile`; artifact cards themselves have no mobile alternative and still toggle the document ID. Once artifact extraction is fixed, mobile needs an explicit document destination or clearly disabled action, not an apparently successful toggle with no visible panel. The desktop close button also has only an X icon, no accessible name. **Repair:** provide a full-screen mobile document route/sheet and label the existing close button. [Route:710-720](../../apps/web/src/app/(main)/chat/[conversationId]/page.tsx#L710-L720), [toggle](../../apps/web/src/components/chat/ArtifactCard.tsx#L31-L54), [close button](../../apps/web/src/components/canvas/CanvasPanel.tsx#L88-L95).

14. **Maintenance/performance — Manual memo contracts omit rendered fields. High confidence about omissions, visible staleness needs reproduction.** `ChatMessage`'s comparator ignores `model`, token counts, first-token/generation timestamps, routing reasoning, retry count, sender image and other fields rendered inside the component. An update to one of those fields with unchanged content/status can be skipped. Meanwhile `MessageItemContent` receives the entire changing `grouped` array, reducing the value of shallow memoization. **Repair:** prefer stable typed message view models plus default memo, or explicitly test every deliberately ignored field; do not enable the React Compiler as an unresearched cure. It is explicitly disabled in Next config, and TypeScript build errors are currently ignored. 15. **Maintenance/performance — Streaming component identity and Mermaid effects invite repeated work. Static inference.** `createMarkdownComponents(isStreaming)` creates new component function identities on every buffer render, rather than memoizing them. If used as React element types by Streamdown, custom blocks can remount and lose state. Mermaid receives a fresh inline config and its render effect depends on that config; the effect does not guard `isStreaming`, despite the comment claiming no streaming render attempts. Whole-code Shiki highlighting is rescheduled whenever code changes; idle scheduling does not make that computation incremental. **Repair:** stabilize component/config identities, explicitly skip diagram rendering while streaming, cancel stale async diagram results, and benchmark incremental block highlighting before changing libraries. [Factory use:114-154](../../apps/web/src/components/chat/MarkdownContent.tsx#L114-L154), [recreation:319-327](../../apps/web/src/components/chat/MarkdownContent.tsx#L319-L327), [Mermaid effect:92-186](../../apps/web/src/components/chat/MermaidRenderer.tsx#L92-L186), [streaming branch:232-243](../../apps/web/src/components/chat/MermaidRenderer.tsx#L232-L243), [highlight work](../../apps/web/src/components/chat/CodeBlock.tsx#L39-L69).

16. **Maintenance/performance — Pagination limits DOM, not all conversation work. Static scaling risk.** Alongside the 50-row active-path page, the cache subscribes to the complete message tree, reads every cached conversation row, and compares full JSON documents before changed-row writes. Per-message source-copy queries, branch/notes components, live cache queries and global event listeners remain in mounted messages; below 500 grouped items all of them mount. The sidebar also maps every conversation, although prefetch is sensibly capped. **Repair:** profile this pipeline with real history fixtures, consider a lightweight branch topology subscription separated from content, bound metadata/query work to loaded/visible rows, and retain the current authorized-tree deletion correctness. No latency/memory number was measured. ### Inferences

- **Fix the first six contract defects before interpreting visual QA results.** Missing artifacts, broken source targets, phantom sends, runaway pagination and invalid focus colors can make a well-designed screen fail the core task; they are better scoped than a component-library replacement. [Artifact consumer](../../apps/web/src/components/chat/ArtifactList.tsx#L23-L55), [source handler](../../apps/web/src/components/chat/MarkdownContent.tsx#L180-L198), [send failure](../../apps/web/src/lib/hooks/mutations/useSendMessage.ts#L142-L174), [pagination](../../apps/web/src/app/(main)/chat/[conversationId]/page.tsx#L324-L342), [focus CSS](../../apps/web/src/app/globals.css#L373-L409).
- **Move linkification into parsed text nodes.** Current regex exclusions recognize only closed triple-backtick and single-backtick regions, and citation replacement does not exclude existing markdown links. Partial fences, tilde fences, multiple-backtick inline code and numeric link labels can be transformed incorrectly; the language regex also only captures `\w+`, so labels such as `c++` are truncated. This is a parser-contract risk, not a claim that all such examples were executed. [Regex transforms](../../apps/web/src/components/chat/MarkdownContent.tsx#L231-L283), [language parsing](../../apps/web/src/components/chat/MarkdownContent.tsx#L114-L119), [duplicated worker transforms](../../apps/web/src/lib/markdown/worker.ts#L81-L110).
- **Treat cache hashes as identity hints, not proof of content identity.** Markdown cache keys are only a 32-bit hash and store no original-content verification. A collision could show another answer's HTML; capacity/TTL bounds help memory but do not eliminate collisions. A full-content key or verified secondary identity would be a small defensive improvement. [Hash and lookup](../../apps/web/src/lib/markdown/cache.ts#L23-L51), [stored entry](../../apps/web/src/lib/markdown/cache.ts#L57-L69).

## 3. What should modernization preserve, improve and verify?

### Takeaway

Preserve the current indigo/rose identity and durable local-first architecture. Modernize around one reliable transcript/render contract, accessible interaction primitives and a measured performance budget; the tentative visual direction below is a proposal, **not a BK-approved design**. [Identity tokens](../../apps/web/src/app/globals.css#L148-L239), [durability requirement](../../AGENTS.md#L21-L26), [state architecture](../../apps/web/src/hooks/useCacheSync.ts#L181-L215).

### Cited Findings

#### Existing visual identity and grounded opportunities

- **Identity:** “Obsidian Void” dark mode uses deep indigo/violet surfaces and rose-quartz primary accents; “Stardust” light mode uses warm cream, amber and orange. Mesh gradients and grain supply atmosphere. Manrope carries body/display text and JetBrains Mono supplies utility/code; Syne is loaded but `--font-display` currently resolves to Manrope. Rounded asymmetric message bubbles use translucent fills, blur, generous padding, shadows, hover borders and small metadata. This is not an unstyled starter chat.
