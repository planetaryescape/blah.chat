# Durable chat, generation, agents and tools

## How does the current generation journey work?

### Takeaway

Keep the Convex-backed message lifecycle. Refresh resilience is real in the design, but it is not the same guarantee as crash-resumable provider/tool execution. Most repairs belong at admission, tool-output conversion, accounting and terminal-state boundaries, not in a replacement chat stack.

### Inferences

- Refresh/tab-close resilience is a property worth preserving. Process death during a provider call is different: the action has no durable program counter or persisted tool-result replay protocol. Recovery currently offers an error/retry experience, not transparent continuation. This follows from the scheduled-action contract and the in-memory accumulators above.
- `chat.ts:306-307` says nested mutations commit independently. Do not use that comment as evidence of a partial-write bug. Convex documents transactionally scheduled mutations; the next implementation should verify nested mutation transaction semantics against the pinned runtime before changing admission on that assumption. [Comment](../../packages/backend/convex/chat.ts#L305-L307), [Convex mutation transactions](https://docs.convex.dev/functions/mutation-functions#transactions).

### Gaps

- No deployed environment, provider credential availability, production latency, failure frequency, user tier distribution or live trace was inspected. Severity below describes impact when a reachable condition occurs, not incident frequency.
- Existing Eve directories contain generated runtime/build/results artifacts in this checkout, not a production import path. One readable scripted summary reports approval deduplication and cancellation successes, but filesystem persistence and crash-during-tool cases time out. These are useful experiment questions, not production guarantees or grounds for deleting the experiment. ## Which failures are supported by current code?

### Takeaway

Prioritize tool-result integrity, usage correctness, destructive retry and common admission. The defects below do not require a new agent framework. Several existing tests verify helpers or stop/error entry points but never complete a successful multi-step generation.

### Cited findings

#### G1. Tagged tool output breaks the structured result contract

**P1, definite contract defect, high confidence.** Affects calculator/search/task/document results, tool success labels and web citations in normal tool-capable chat.

`buildToolsAsync` wraps every executable tool. The wrapper returns an XML-like string containing the JSON instead of the original result object. Main generation stores that string as the normalized result. UI decodes JSON once and then accesses object fields; the decoded value remains a string. Calculator displays `= undefined`; failed task/memory calls can appear successful; search source extraction finds no `result.results`. Analytics checks `.error` on the same string and calls it successful. [packages/backend/convex/generation/tools.ts:304-306,336-354](../../packages/backend/convex/generation/tools.ts#L304-L354), [generation.ts:887-939](../../packages/backend/convex/generation.ts#L887-L939), [apps/web/src/components/chat/ChatMessage.tsx:239-250](../../apps/web/src/components/chat/ChatMessage.tsx#L239-L250), [apps/web/src/components/chat/ToolCallDisplay.tsx:95-105](../../apps/web/src/components/chat/ToolCallDisplay.tsx#L95-L105), [apps/web/src/components/chat/toolCallUtils.ts:99-127](../../apps/web/src/components/chat/toolCallUtils.ts#L99-L127), [packages/backend/convex/generation/sources.ts:151-168](../../packages/backend/convex/generation/sources.ts#L151-L168).

Repair: retain native JSON as the tool execution/storage contract. Apply data-boundary text only when converting a tool result into the model-facing SDK output, using the pinned SDK's tool conversion hook or a typed adapter. Do not teach every renderer to regex-parse a security wrapper. Preserve the prompt-injection defense's intent; marker text alone is not a security boundary.

Acceptance: run the real tool builder with mocked tool backends for calculator success, task failure and Tavily results. Drive the action through tool-call/result events. Assert native JSON in Convex, correct UI label/error state, citations persisted, and tagged data only in the next model request.

#### G2. Multi-step and cancelled text usage is under-recorded

**P1, definite defect, high confidence.** Affects cost badges, monthly spend/budget enforcement and tool-heavy conversations.

The pinned lockfile is AI SDK **6.0.89**. Its `usage` is the last step, while `totalUsage` sums all steps. Chat enables up to 15 steps but bills `await result.usage`; continuation usage is added only to that last-step amount. [bun.lock:2326](../../bun.lock#L2326), [pinned SDK StreamTextResult contract](https://github.com/vercel/ai/blob/ai%406.0.89/packages/ai/src/generate-text/stream-text-result.ts), [packages/backend/convex/generation.ts:648-653](../../packages/backend/convex/generation.ts#L648-L653), [generation.ts:1157-1203](../../packages/backend/convex/generation.ts#L1157-L1203).

Stop exits before reading any usage. The cancellation fixture explicitly expects that behavior. `completeMessage` also records stopped/error **image** spend but not stopped/error text spend. Failed attempts calculate only a telemetry estimate, using `args.modelId` rather than the resolved auto model; they do not write those costs to usage records. [generation.ts:1035-1043](../../packages/backend/convex/generation.ts#L1035-L1043), [packages/backend/convex/__tests__/launchBlockers.test.ts:561-598](../../packages/backend/convex/__tests__/launchBlockers.test.ts#L561-L598), [packages/backend/convex/messages.ts:812-841](../../packages/backend/convex/messages.ts#L812-L841), [generation.ts:1637-1666](../../packages/backend/convex/generation.ts#L1637-L1666). Budget admission relies on recorded spend. [packages/backend/convex/chat.ts:144-157](../../packages/backend/convex/chat.ts#L144-L157).

Repair: record each completed provider step and attempt under an idempotent usage key, including cancelled/failed attempts with known provider usage. Sum for display. For unknown partial usage, store an explicitly estimated amount rather than silently zero. Calculate price tiers per provider request, not from all steps combined, since tier thresholds apply to a request's input. Existing cache-hit normalization is worth retaining. [packages/ai/src/utils.ts:120-161](../../packages/ai/src/utils.ts#L120-L161).

Acceptance: fake a three-step stream with different input/cache/output/reasoning usage and one continuation. Assert the sum of per-request costs, one usage write per step, no charge duplication on duplicate settlement, and retained stopped status when cancellation settles already-completed steps. Check auto retry records each failed model separately.

#### G3. Conversation token accounting happens twice and mixes lifetime spend with context size

**P2, definite defect, high confidence.** Affects context indicators, model-switch blocking and auto-compression decisions.

`completeMessage` schedules `updateConversationTokenUsage`, then generation calls that same additive mutation again. It increments per-model totals and `messageCount`, and also adds the billed tokens into the legacy context estimate. The parallel generation branch also writes a freshly calculated context estimate; interleaving the scheduled mutation changes the final displayed value. [packages/backend/convex/messages.ts:885-895](../../packages/backend/convex/messages.ts#L885-L895), [packages/backend/convex/generation.ts:1523-1555](../../packages/backend/convex/generation.ts#L1523-L1555), [packages/backend/convex/conversations/tokens.ts:96-160](../../packages/backend/convex/conversations/tokens.ts#L96-L160).

The estimate counts `listInternal`'s latest 1000 messages across all branches, whereas the provider sees 30 complete ancestors plus serialized attachments and system prompts. Memory text is already embedded in system prompts and is also passed separately for counting. Thus even removing one duplicate increment does not make the context gauge describe the request. [generation.ts:1527-1536](../../packages/backend/convex/generation.ts#L1527-L1536), [messages.ts:550-565](../../packages/backend/convex/messages.ts#L550-L565), [generation.ts:406-411](../../packages/backend/convex/generation.ts#L406-L411), [packages/backend/convex/lib/prompts/systemBuilder.ts:118-124](../../packages/backend/convex/lib/prompts/systemBuilder.ts#L118-L124), [packages/backend/convex/tokens/counting.ts:107-129](../../packages/backend/convex/tokens/counting.ts#L107-L129). The page uses this gauge to block sends and decide auto-compression. [apps/web/src/app/(main)/chat/[conversationId]/page.tsx:137-173](../../apps/web/src/app/%28main%29/chat/%5BconversationId%5D/page.tsx#L137-L173).

Repair: separate an idempotent lifetime usage aggregate from a replace-only estimate of the exact serialized next request. Give one place ownership of each update.

Acceptance: settle one generation, drain its scheduled accounting, assert per-model messageCount increases once. Create a huge inactive sibling and a small active path; context estimates and send blocking must reflect only the active serialized request. Include identity memory and attachments once.

#### G4. User-message retry deletes unrelated branches

**P1, definite destructive defect, high confidence.** Affects a user retrying an older failed turn after creating other branches/comparison responses.

`retryMessage` finds the next assistant by chronological array position, then deletes **every subsequent message in the conversation**, not the failed assistant or its descendants. It directly deletes message rows without their attachments/tool calls/sources. The retry button on a user message calls this mutation when the displayed next message is an error; assistant error "Try Again" uses the safer sibling regeneration path. [packages/backend/convex/chat.ts:1040-1091](../../packages/backend/convex/chat.ts#L1040-L1091), [apps/web/src/components/chat/MessageActions.tsx:72-75,258-268](../../apps/web/src/components/chat/MessageActions.tsx#L72-L268), [apps/web/src/components/chat/ChatMessage.tsx:56-63](../../apps/web/src/components/chat/ChatMessage.tsx#L56-L63).

Repair: route user-message retry to the same immutable sibling-creation operation as assistant regeneration. Resolve the target through parent IDs, never global chronological adjacency. Do not delete the old failed attempt or unrelated tree records.

Acceptance: root user -> failed assistant on branch A, with later successful branch B plus attachments/tool calls. Retry A through the actual user-message action. Every original message/metadata row and branch B must remain; the new assistant must parent the intended user and use the right context. Also test a comparison sibling inserted between chronological neighbors.

#### G5. Conversation locking is incomplete and expires during healthy generation

**P1, definite admission defect, high confidence.** Affects long answers, CLI/web overlap, regeneration/edit/merge during an active answer and comparison fanout.

Web send acquires a lock, but `acquireLock` deletes it after 60 seconds without checking message progress. No stream heartbeat renews `lockedAt`. Cron also deletes old locks unconditionally. `startGeneration` starts a pending row even if it has no lock or another run owns the lock. Regenerate/edit/merge/consolidation/CLI paths schedule work without acquiring this lock, so those public entry points bypass the advertised single-run policy. [packages/backend/convex/lib/generationLock.ts:18,45-81](../../packages/backend/convex/lib/generationLock.ts#L18-L81), [generationLock.ts:254-277](../../packages/backend/convex/lib/generationLock.ts#L254-L277), [packages/backend/convex/messages.ts:636-664](../../packages/backend/convex/messages.ts#L636-L664), [packages/backend/convex/chat.ts:609-637](../../packages/backend/convex/chat.ts#L609-L637), [chat.ts:815-845](../../packages/backend/convex/chat.ts#L815-L845), [chat.ts:1517-1544](../../packages/backend/convex/chat.ts#L1517-L1544), [packages/backend/convex/conversations/consolidation.ts:157-195](../../packages/backend/convex/conversations/consolidation.ts#L157-L195), [packages/backend/convex/cliAuth.ts:362-435](../../packages/backend/convex/cliAuth.ts#L362-L435).

Repair: introduce one transactional `admitGeneration` helper used by every paid generation entry point. It creates the pending target, reserves the conversation/comparison run and schedules work. Use an owned run/attempt ID and progress lease rather than a fixed age from initial admission. Preserve the existing lock-ID protection on release. Decide explicitly whether branches may generate concurrently; enforce that policy rather than accidentally allowing it.

Acceptance: fake time past 61 seconds while a provider continues healthy progress, then issue a second web/CLI/regenerate/edit request. It must queue or reject according to the chosen policy. Stop A, admit B, then deliver A's release/recovery/finish events; none may remove B's lock. Test comparison pending counts with one success, one failure and one stop.

#### G6. Scheduled generation drops user custom instructions

**P2, definite defect, high confidence.** Affects normal scheduled chat and API-key CLI personalization.

#### G8. Cancellation does not cancel a silent provider or already-running write tool

**P1 reliability risk with definite missing cancellation propagation, high confidence in mechanism, unmeasured incidence.** Affects stop during provider stalls, task writes and external integrations.

The "10ms" stop interval runs only inside `for await`, after a chunk arrives. A provider/tool that is silent never triggers that polling check. No separate run monitor/timeout is installed. Tool factories such as task management do not consume SDK `abortSignal`, and Composio wrappers execute the original action without checking durable run state. A stopped message and released conversation lock therefore do not prove its side effects have stopped. The non-streamed fallback continuation also receives no abort signal. [packages/backend/convex/generation.ts:803-848](../../packages/backend/convex/generation.ts#L803-L848), [generation.ts:1071-1096](../../packages/backend/convex/generation.ts#L1071-L1096), [packages/backend/convex/ai/tools/taskManager.ts:120-139](../../packages/backend/convex/ai/tools/taskManager.ts#L120-L139), [packages/backend/convex/composio/tools.ts:97-122](../../packages/backend/convex/composio/tools.ts#L97-L122).

#### G9. Post-completion work can turn a successful answer into an error

**P2, definite state-transition defect, high confidence; failure frequency untested.** Affects an answer completed successfully followed by token-count or conversation-update failure.

The action completes the message and releases its lock, then awaits timestamp/token-count/post-processing inside the same broad try. Catch only exempts missing/stopped messages, not complete ones. `markError` only exempts stopped messages, so any later thrown exception can change complete -> error. The user can see a valid answer followed by "Unable to generate response" and retry it. Analytics itself catches its own errors, so PostHog failure alone is **not** evidence of this defect. #### G10. `clientMessageId` reconciles UI but does not make send idempotent

**P2, definite missing deduplication with conditional duplicate-spend risk, high confidence.** Affects a lost HTTP acknowledgment, offline replay, multi-tab retries and duplicate sends after lock expiry/completion.

The ID travels from HTTP to `chat.sendMessage` and is stored, but the send handler never checks for an existing row with that ID. The only backend occurrences are validators/storage/pass-through and the schema comment calls it optimistic reconciliation. #### G11. Tool-only fallback continuation constructs obsolete SDK messages

#### G12. Compaction summarizes other branches and drops the transcript suffix

**P2, definite behavior with context-integrity risk, high confidence.** Affects manual/automatic compaction of long or branched chats.

Repair: select active ancestry consistently for generation and compaction. Budget by serialized tokens with output reserve; preserve a recap plus recent turns rather than a raw first-N-characters prefix. Make the intentional context-retention policy visible and testable.

Acceptance: place a distinctive secret on an inactive branch, an old requirement on the active path, and a recent correction after 16,000 characters. ## What should be kept, repaired and verified next?

### Takeaway

Keep durable Convex rows, server-side generation and account-scoped subscriptions. Extract four narrow modules only after the first regression tests expose the contract failures: generation admission/settlement, provider message conversion, tool execution outcomes and per-call usage accounting.
